# src/server/lib – Server-Helfer

Einziger Ort für generische Server-Helfer. **Vor dem Anlegen eines Helfers greppen**, ob es ihn
schon gibt (auch in `src/shared`). Ownership je Datei (R0-02, ADR-017) – ein Paket ändert nur seine
eigenen Dateien; fehlt etwas in einer fremden Datei, wird es im Bericht angefragt (kein Duplikat):

| Datei | Owner | Inhalt |
| --- | --- | --- |
| `logger.ts` | WP-10 | der Logger (pino): `logger` (Singleton), `createLogger`, `initLogging` (Rotation per pino-roll unter `PARALLAX_HOME/logs`, Pretty im Dev-Modus), `registerSecret`/`unregisterSecret`, `redactText` (registrierte Secrets, Bearer, `sk-ant-…`, Cookie-Werte, `*_TOKEN=` und JSON-Schlüssel `"…TOKEN|SECRET|PASSWORD|API_KEY":"…"` in jeder Tiefe), `REDACT_PATHS`, `shouldLogRepeated(count)` (wiederholte Fehler: die ersten 20, dann jeder 100., R3-05) |
| `ids.ts` | WP-10 | `newId('en' \| 'cv' \| 'dc' \| 'pf')`, `newUuid()`, `newToken()` (32 Byte base64url) mit `node:crypto` |
| `paths.ts` | WP-10 | Pfad-Helfer: `assertSafePath(path)` (→ `CommandError(PATH_REJECTED, {reason})`), `checkCwd(cwd)` (+ `CWD_NOT_FOUND`/`CWD_NOT_DIRECTORY`), `resolveAllowedPath(path, roots)` (realpath + Allowlist, `PATH_NOT_ALLOWED`; Grenze: Datei-Symlinks auf UNC, R1-17), `fsErrorCode(error)` |
| `process.ts` | WP-11 | `runFile`, `RunFileFn`, `RunFileOptions`/`RunFileResult`, `spawnHidden` (`SpawnHiddenOptions` mit `onStderr`), `killProcessTree` (`taskkill /PID <pid> /T /F`), `assertSpawnableFile` (nur **absolute** `.exe`-Pfade, R1-04), `systemTool(name)` (System32-Pfad), `isProcessAlive` (Sofort-Vorfilter), `errnoCode`; Prozessabfragen **dreiwertig** (R2-02, ADR-051): `queryProcesses({pids, parentPids})` → `{kind:'ok', processes} \| {kind:'unknown', reason, detail}` (eine gebündelte CIM-Abfrage, ≤ `PROCESS_QUERY_MAX_CLAUSES` (100) Klauseln je Aufruf, Default-Timeout `PROCESS_QUERY_TIMEOUT_MS` 60 s, `unknown` heißt nie „weg“), `processInfo(pid)` → `found`/`missing`/`unknown`, `childProcesses(pid)` (dreiwertig; nur Shutdown-Sweep, kein Kinder-Pfad der Waisen-Bereinigung bis nach WP-22, ADR-052), `processStartTime`, `processQueryFilters`, `parseProcessQueryOutput`, Typen `ProcessInfo`, `ProcessQueryResult`, `ProcessLookup` |
| `async.ts` | Koordinator (R2-10, ADR-055) | `toError`, `sleep`, `realSetImmediate`/`nextMacrotask` (vor Fake-Timern gesichert), `settleWithin(work, ms)` → `done`/`failed`/`timeout` (nie ein Reject; Aufräum- und Shutdown-Schritte, R3-10) – statt Kopien in backend/sessions/launcher/store |
| `fs.ts` | Koordinator (R2-10, ADR-055) | `withFsRetry` (EPERM/EBUSY/EACCES, `DEFAULT_RETRY_DELAYS_MS` ≈ 1,6 s), `isTransientFsError`, `writeFileAtomic(file, data, {fs?, backup?, retryDelaysMs?})` (Temp-Datei mit fsync + Rename, optional `.bak`), `FsOps`/`nodeFsOps` (Test-Naht) – aus `store/jsonStore.ts` verschoben (dort re-exportiert); Nutzer: Stores, `launcher/{lockFile,serverProcess}.ts` |
| `homeLock.ts` | Koordinator (R2-05, ADR-054, ADR-062) | `acquireHomeLock(home)` → `{kind:'acquired', lock}` \| `{kind:'busy', pipe, reason: 'in_use'\|'access_denied'}` (Named-Pipe-Mutex je `PARALLAX_HOME`, frei beim Prozessende; `busy` → Exit 5, `access_denied` = Pipe eines anderen Windows-Benutzers, R3-16), `HomeLock` (`pipe`, `exclusive`, `release()`), `homeLockKey`, `homeLockPipeName`; allgemein `acquireDirectoryLock(kind, dir)` / `directoryLockPipeName(kind, key)` mit `kind` `home`/`launch`/`build` (Launcher: ein Start je Home, ein Build je Checkout, R3-04) – verdrahtet in `main.ts` (vor Log und Stores) und `launcher/launcher.ts` |
| `homeAccess.ts` | Koordinator (R2-13, ADR-056) | `checkHomeAccess(home)` → `private`/`shared`/`missing`/`unknown` (SDDL per `Get-Acl`, SID per `whoami`, wirft nie; Nutzer: `pnpm preflight`), `logHomeAccess` (Warnung beim Serverstart, `app/compose.ts`), `parseSddlDacl`, `otherReaders`, `parseWhoamiSid`, Typen `HomeAccess`, `SddlAce` – nur Warnung, keine ACL-Änderung |
| `windows.ts` | WP-11 | `FsProbe`/`nodeFsProbe`/`createMemoryFs` (geprüfter Dateizugriff, Fake für Tests), `getEnvVar` (case-insensitiv), `searchPath` (where im Prozess, nie das cwd), `resolveCmdShim` (npm-Shim → `.exe`), `resolveExecutable(name, env)` (nackter Name → absolute `.exe`) – aus `claude/` verschoben (R1-08) |
| `registry.ts` | WP-11 | `reg.exe` per System32-Pfad: `regQuery` (`/ve`), `regKeyQuery`, `parseRegDefaultValue`, `parseRegValues`, `expandRegValue`, `readPersistentEnvironment` (HKCU/HKLM `Environment`, für `buildEnv`, ADR-021) |
| `edge.ts` | WP-11 | `findEdge({regQuery, fs, env})` (App Paths HKCU/HKLM 64/32, dann Program Files/LocalAppData) – für Preflight und Launcher (WP-21), aus `claude/preflight.ts` verschoben (R1-08) |

Signaturen: `docs/architecture.md` §2.2. Die **Pfadregeln** selbst (UNC/Device/ADS, reservierte
Namen, case-insensitiver Vergleich) stehen nur in `@shared/paths`; `paths.ts` ruft sie auf und
implementiert sie nicht neu. Prozesse: immer `shell: false`, `windowsHide: true`, nur absolute
`.exe`-Pfade (C.7, R1-04) – nackte Programmnamen vorher mit `resolveExecutable`/`systemTool`
auflösen (libuv würde sonst zuerst im `cwd` des Kindes suchen).
