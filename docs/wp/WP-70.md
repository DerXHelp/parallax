## 0. Ausgangslage

**Anmelden (Punkt 25).** Nutzer: „Ich möchte den Anmelde-Knopf haben“ (gegen die Empfehlung, nur den Fehlertext zu
verbessern). Heute: Anmeldefehler enden als `CLAUDE_AUTH_FAILED` („Claude Code konnte sich nicht anmelden. Prüfe deine
Anmeldung.“), Remote Control als `REMOTE_CONTROL_AUTH` („`claude` im Terminal starten und /login eingeben“); der
Profil-Status kommt aus `claude auth status` (`src/server/claude/authStatus.ts`, `shell/new-session/profile-status.tsx`,
`features/profiles/components/TestResult.tsx`). Abgeleitet aus dem gebündelten Code von `claude` 2.1.323 (nicht live
geprüft – Live-Test nur in der gemeinsamen Abnahme mit isoliertem Profil):
- Interne Query-Methoden des SDK 0.3.322 (nicht in `sdk.d.ts`, zur Laufzeit prüfen wie ADR-170):
  `claudeAuthenticate(loginWithClaudeAi: boolean)` → Control `claude_authenticate` → `{ manualUrl, automaticUrl }`;
  `claudeOAuthCallback(authorizationCode, state)` → `claude_oauth_callback`; `claudeOAuthWaitForCompletion()` →
  `claude_oauth_wait_for_completion`.
- Das CLI startet den OAuth-Ablauf mit `skipBrowserOpen: true` (der Host öffnet den Link) und, wenn möglich, einen
  lokalen Rückruf-Listener; nur dann gibt es `automaticUrl` (Rückruf an `localhost:<port>`, Abschluss ohne Code). Ohne
  Listener nur `manualUrl`: die Seite zeigt einen Code, der per `claudeOAuthCallback(code, state)` zurückgeht (der
  angezeigte Text hat erfahrungsgemäß die Form `code#state` – beim Einfügen trennen, tolerant parsen).
- Gleiche Versuche binnen 10 min werden zusammengelegt (`tengu_oauth_flow_joined`, gleiche URLs).
- `claudeOAuthWaitForCompletion()` endet nach dem Login mit `{ account: { email, organization, subscriptionType,
  tokenSource, apiKeySource, apiProvider }, … }` – **E-Mail und Organisation nie loggen, nie persistieren, nicht an die
  UI** (nur `subscriptionType`). Fehler u. a. „No active claude_authenticate flow“, „Login blocked: this machine's
  managed settings do not permit signing in …“ (Richtlinie), Org-Pin abgelehnt.
- Die Anmeldung gilt je Konfigurationsordner, also für **alle Sessions eines Profils**.

**Ausgabestil (Punkt 28).** Nutzer: „Ausgabestil klingt gut, ich möchte das bauen. EffortLevel ist ok, wenn das nur in
Parallax einstellbar ist.“ Live-Probe 13.11.2026 (Haiku, im Projekt-Scratch):
- `initializationResult()`: `output_style: "default"`, `available_output_styles: ["default", "Proactive", "Concise",
  "Explanatory", "Learning"]` (eigene Stile des Nutzers kämen dazu).
- `updateSettings('localSettings', { outputStyle: 'Explanatory' })` (öffentlich) → nach 65 ms
  `<cwd>\.claude\settings.local.json` = `{ "outputStyle": "Explanatory" }`; keine `.gitignore` angelegt (auch nicht im
  git-Repo); `getSettings().effective.outputStyle` sofort `"Explanatory"`; `system/init` des nächsten Turns derselben
  Session meldet `output_style: "Explanatory"` (vorher `"default"`).
- Laut SDK erlaubt `updateSettings` je Datei nur eine Schlüsselliste (localSettings: `outputStyle`; userSettings:
  `effortLevel`) und lehnt Sitzungen ab, deren `settingSources` die Zielquelle ausschließen.
- Effort bleibt wie bisher nur in Parallax (kein Schreiben nach `~/.claude/settings.json`).

### 3.4 ADR-Vorschläge (Nummern vergibt der Koordinator; nächste freie 188)
- **Anmelden in einem eigenen, kurzlebigen Prozess je Profil**, nicht im Prozess einer laufenden Session.
  - Die Anmeldung wird gebraucht, wenn keine Session läuft (Neue Session, Profiltest, Banner) oder wenn die Session
    gerade wegen des Fehlers steht.
  - Der Prozess einer Session hat die Projekt-Settings und Hooks und ist im Turn beschäftigt.
  - Ein eigener Prozess hat ein neutrales `cwd`, `settingSources: []`, kein Transkript und ein sauberes Ende
    (Abbrechen = Prozess schließen).
  - Die Anmeldung gilt je `CLAUDE_CONFIG_DIR`, also für alle Sessions des Profils.
- **Anmeldeablauf als Profilzustand, Befehle antworten sofort** (Muster ADR-170):
  - Alle Clients sehen denselben Stand.
  - Ein Fehler-Item blendet seinen Knopf über `login.at` aus, ohne eigenen Client-Zustand.
  - Der Dialog ist nur eine Ansicht; Schließen beendet nichts.
- **Kontodaten verlassen das Backend nie**:
  - Das zod-Schema der Antwort kennt nur `subscriptionType`.
  - CLI-Fehlertexte werden zu `reason`-Codes klassifiziert.
  - stderr des Anmelde-Prozesses nur als Länge ins Log.
- **Ausgabestil über `updateSettings('localSettings')` im Prozess der Session**, nicht per Dateischreiben:
  - Das CLI besitzt Format, Merge und Schlüsselprüfung von `settings.local.json`.
  - Der Stil gilt je Projekt. Andere laufende Sessions zeigen ihn erst mit ihrem nächsten `init`.
- **Nicht-modaler Anmelde-Dialog, modal nur aus modalen Dialogen**: Eine nicht-modale Radix-Ebene außerhalb des
  React-Baums eines modalen Dialogs würde diesen schließen (Klick „außerhalb“).
