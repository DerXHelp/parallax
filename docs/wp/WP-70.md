# WP-70 – Anmelden aus Parallax und Ausgabestil je Projekt

Branch `wp/70` von `feature/ux-feedback` **nach dem Merge von WP-69** (gleiche Contract-Dateien).
Auftraggeber: Koordinator. Nutzerentscheidungen 13.11.2026 (`docs/wp/SDK-MOEGLICHKEITEN.md` §4, Punkte 25 und 28).

## 0. Ausgangslage

**Anmelden (Punkt 25).** Nutzer: „Ich möchte den Anmelde-Knopf haben“ (gegen die Empfehlung, nur den Fehlertext zu
verbessern). Heute: Anmeldefehler enden als `CLAUDE_AUTH_FAILED` („Claude Code konnte sich nicht anmelden. Prüfe deine
Anmeldung.“), Remote Control als `REMOTE_CONTROL_AUTH` („`claude` im Terminal starten und /login eingeben“); der
Profil-Status kommt aus `claude auth status` (`src/server/claude/authStatus.ts`, `shell/new-session/profile-status.tsx`,
`features/profiles/components/TestResult.tsx`). Abgeleitet aus dem gebündelten Code von `claude` 2.1.323 (nicht live
geprüft – Live-Test nur in der gemeinsamen Abnahme mit isoliertem Profil):
- Interne Query-Methoden des SDK 0.3.322 (nicht in `sdk.d.ts`, zur Laufzeit prüfen wie ADR-170):
  `claudeAuthenticate(loginWithClaudeAi: boolean)` → Control `claude_authenticate` → `{ manualUrl, automaticUrl }`;
  `claudeOAuthCallback(authorizationCode, state)` → `claude_oauth_callback`; `claudeOAuthWaitForCompletion()` →
  `claude_oauth_wait_for_completion`.
- Das CLI startet den OAuth-Ablauf mit `skipBrowserOpen: true` (der Host öffnet den Link) und, wenn möglich, einen
  lokalen Rückruf-Listener; nur dann gibt es `automaticUrl` (Rückruf an `localhost:<port>`, Abschluss ohne Code). Ohne
  Listener nur `manualUrl`: die Seite zeigt einen Code, der per `claudeOAuthCallback(code, state)` zurückgeht (der
  angezeigte Text hat erfahrungsgemäß die Form `code#state` – beim Einfügen trennen, tolerant parsen).
- Gleiche Versuche binnen 10 min werden zusammengelegt (`tengu_oauth_flow_joined`, gleiche URLs).
- `claudeOAuthWaitForCompletion()` endet nach dem Login mit `{ account: { email, organization, subscriptionType,
  tokenSource, apiKeySource, apiProvider }, … }` – **E-Mail und Organisation nie loggen, nie persistieren, nicht an die
  UI** (nur `subscriptionType`). Fehler u. a. „No active claude_authenticate flow“, „Login blocked: this machine's
  managed settings do not permit signing in …“ (Richtlinie), Org-Pin abgelehnt.
- Die Anmeldung gilt je Konfigurationsordner, also für **alle Sessions eines Profils**.

**Ausgabestil (Punkt 28).** Nutzer: „Ausgabestil klingt gut, ich möchte das bauen. EffortLevel ist ok, wenn das nur in
Parallax einstellbar ist.“ Live-Probe 13.11.2026 (Haiku, im Projekt-Scratch):
- `initializationResult()`: `output_style: "default"`, `available_output_styles: ["default", "Proactive", "Concise",
  "Explanatory", "Learning"]` (eigene Stile des Nutzers kämen dazu).
- `updateSettings('localSettings', { outputStyle: 'Explanatory' })` (öffentlich) → nach 65 ms
  `<cwd>\.claude\settings.local.json` = `{ "outputStyle": "Explanatory" }`; keine `.gitignore` angelegt (auch nicht im
  git-Repo); `getSettings().effective.outputStyle` sofort `"Explanatory"`; `system/init` des nächsten Turns derselben
  Session meldet `output_style: "Explanatory"` (vorher `"default"`).
- Laut SDK erlaubt `updateSettings` je Datei nur eine Schlüsselliste (localSettings: `outputStyle`; userSettings:
  `effortLevel`) und lehnt Sitzungen ab, deren `settingSources` die Zielquelle ausschließen.
- Effort bleibt wie bisher nur in Parallax (kein Schreiben nach `~/.claude/settings.json`).

## 1. Auftrag

### Pflichtlektüre

schlafende Sessions, Session-Info), `docs/wp/WP-62.md` (cli-check-Proben, Profilfelder nullable).

### 1.1 Anmelden (Server)
- Anmeldung **je Profil**: eigener kurzlebiger `claude`-Prozess des Profils (Env über `buildEnv`, neutrales
  Arbeitsverzeichnis im Parallax-Home, kein Prompt, kein Transkript), schließt nach Erfolg, Abbruch oder 10 min; oder
  – falls einfacher und gleich robust – der Prozess einer laufenden Session des Profils. Begründung in §3.
- Ablauf: Start → URLs → `automaticUrl` (sonst `manualUrl`) über den vorhandenen Weg `link.open` im Standardbrowser
  öffnen → im Hintergrund `claudeOAuthWaitForCompletion()`; Code-Eingabe → `claudeOAuthCallback`. Zustand je Profil
  (`idle`/`waiting`/`done`/`failed` mit Fehlercode) an alle Clients; nach Erfolg Auth-Status des Profils neu lesen,
  Anmeldefehler-Hinweise verschwinden, Remote Control kann neu verbinden.
- Methoden zur Laufzeit prüfen (fehlen sie → Zustand „nicht verfügbar mit dieser claude-Version“ + Rückfall auf den
  Terminal-Hinweis). Keine Kontodaten in Logs/Dateien/WS außer `subscriptionType`.

### 1.2 Anmelden (UI)
- Knopf „Anmelden“ an: Fehler-Item/Banner bei `CLAUDE_AUTH_FAILED` (und Assistant-Fehler `authentication_failed`),
  Remote-Control-Fehler `REMOTE_CONTROL_AUTH`, Profil-Status „nicht angemeldet“ (Neue-Session-Dialog, Profile).
- Kleiner nicht-modaler Dialog: „Anmeldung im Browser geöffnet – warte auf Abschluss …“, „Link erneut öffnen“,
  „Link kopieren“, Feld „Code einfügen“ (für den manuellen Weg), Abbrechen; Erfolg „Angemeldet (Max)“, Fehler im Dialog
  (`Alert role="alert"`). en/de.
- Die Fehlertexte `CLAUDE_AUTH_FAILED`/`REMOTE_CONTROL_AUTH` klarer: was passiert ist + „Anmelden“; Terminal-Weg nur
  noch als Rückfall, wenn die Methode fehlt.

### 1.3 Ausgabestil je Projekt
- Session-Zusammenfassung/Detail: aktueller Stil (aus `system/init` je Turn bzw. `initializationResult`) und die
  verfügbaren Stile (Detail).
- Kopfzeilen-„…“-Menü (und Session-Info-Reiter „Status“): „Ausgabestil“ mit Liste + Hinweis „gilt für alle Sessions in
  diesem Projekt (`.claude\settings.local.json`)“. Auswahl → `updateSettings('localSettings', { outputStyle })` im
  Prozess der Session (schlafend: Prozess ohne Turn starten wie bei der Session-Info); wirkt ab dem nächsten Turn.
  Fehler als Toast/`Alert` mit Code.
- Nur `localSettings`/`outputStyle`; nichts anderes schreiben. Externe/archivierte Sessions: Menüpunkt deaktiviert.

### 1.4 `pnpm cli-check` (WP-62)
- Probe: Anmelde-Methoden vorhanden (nur Typprüfung, **nie aufrufen**), `updateSettings` + Rundlauf im isolierten
  Probe-Projekt (Datei geschrieben, `getSettings` bzw. nächstes `init` zeigt den Stil; Rückbau der Datei). Profilfelder
  nullable (`login`, `outputStyle`), Bericht mit „Affected“-Text wie bei den übrigen Proben.

### 1.5 FakeBackend, Tests, E2E, Doku
- Fake: Anmelde-Ablauf (URLs auf eine harmlose Fake-Adresse, Abschluss per Test-Handle/Schlüsselwort, Fehlerfälle
  Richtlinie/abgelaufen), `fake:auth-failed` falls nicht vorhanden; Ausgabestile mit Liste und Wechsel.
- Tests neben dem Code; E2E: Anmelde-Knopf am Fehler → Dialog → Abschluss → Hinweis weg; Ausgabestil wählen → nächster
  Turn meldet den Stil. `link.open` darf im E2E keinen Browser öffnen (vorhandene Test-Weiche nutzen).
- READMEs, `docs/architecture.md`, ADR-Vorschläge in §3, Live-Checkliste (Koordinator, mit isoliertem Profil:
  eigenes `CLAUDE_CONFIG_DIR`, das echte Login bleibt unberührt).

  `login`/`outputStyle` nullable.
