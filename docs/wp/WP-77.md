# WP-77 – Entwürfe synchron

Branch `wp/77` von `feature/multi-host` (`3998a88`). Grundlage: WP-75 §4.5, WP-76 §C (Contracts v5), ADR-210.
Keine Contract-Änderung, keine neue Abhängigkeit.

## 0. Auftrag (kurz)

Der Composer-Entwurf liegt je Eintrag im Server und erscheint in jedem Fenster der Session, auch auf einem anderen
Rechner. Der letzte Schreiber gewinnt, Senden löscht den Entwurf überall, `localStorage` bleibt Zwischenspeicher.

## 1. Server

### 1.1 Store `src/server/store/drafts.ts`
- `createDraftStore({ home, warnings?, debounceMs?, fs?, retryDelaysMs?, now?, logger? })` → `DraftStore` + `close()`;
  Datei `entries/<entryId>/draft.json` (`draftFileSchema`, `schemaVersion: 1`), Pfad über `entryDir` (`draftPath`).
- Eigene Umsetzung statt `JsonStore` (wie `sessions/commandCatalog.ts`): je Eintrag ein Slot mit bekanntem Wert,
  ausstehendem Wert, Timer und einem Schreiber. `save()` validiert (`draftSchema`) und schreibt entprellt (500 ms),
  atomar über `writeFileAtomic` **ohne `.bak`** (ein alter Entwurf soll nie zurückkommen). `save(id, null)` löscht die
  Datei, `remove(id)` sofort (wartet einen laufenden Schreibvorgang ab). `flush()` schreibt alles Ausstehende.
- Geschrieben wird erst, nachdem die Datei gelesen wurde. Kaputtes JSON, falsche `schemaVersion` oder falsche Form →
  Quarantäne `draft.json.corrupt-<zeit>-<rand>` + `STORE_CORRUPT_QUARANTINED` (Gründe `json`, `schema_version`,
  `schema` mit `path`), zählt als „kein Entwurf“. Eine **neuere** Version bleibt unangetastet: kein Entwurf, für diesen
  Eintrag wird nie geschrieben oder gelöscht, Warnung `STORE_VERSION_TOO_NEW` – der Server startet trotzdem.
- Schreibfehler: Wert bleibt ausstehend (nächster `save`/`flush`), einmal `STORE_WRITE_FAILED` bis zum nächsten Erfolg.

### 1.2 Engine (`src/server/sessions/**`)
- `EngineStores.drafts?: DraftStore` (optional; fehlt → `null`, Entwürfe nur im Speicher dieses Serverlaufs).
- `EntryState.draft` + `restoreDraft()` (Start: `recoverEntry` lädt je Eintrag, Fehler → Warnung im Log) +
  `setDraft()` (Store, `detail.patch {draft}`, `publishSummary` → `hasDraft`; Leeren eines leeren Entwurfs ändert
  nichts). `summaryOf(…, { hasDraft })`, `baseView`/`emptyDetail` mit `draft` – die geladene Ansicht zeigt ihn.
- `session.setDraft` (`commands.ts`): in jedem Zustand erlaubt (auch archiviert und extern: in `ARCHIVED_ALLOWED` und
  `EXTERNAL_ALLOWED`), ohne Lifecycle-Lock. Über `LIMITS.draftTotalChars` → `DRAFT_TOO_LARGE {chars, max}`; jedes Paste
  muss wörtlich im Text stehen (`checkPastes`, wie `PromptInput.pastes`). `clientId` = sendendes Fenster,
  `updatedAt` = jetzt, `baseRev` wird nie abgelehnt, eine Abweichung nur geloggt (debug). `null` → `{rev: null}`.
- **Senden löscht:** `session.sendPrompt` merkt sich den Entwurf beim Eingang (synchron, vor jedem `await`) und löscht
  ihn nach erfolgreicher Zustellung, **wenn er sich inzwischen nicht geändert hat** (wer während eines langsamen
  Starts weitertippt, verliert nichts). Ein fehlgeschlagenes Senden lässt ihn stehen.
- `session.remove` → `drafts.remove()` (Fehler nur geloggt). `shutdown()` ruft `drafts.flush()`.
- Testdoppel: `createMemoryDraftStore` in `testing/memoryStores.ts` (`saves`, `removed`, `flushes`, `draft()`),
  Harness-Option `drafts` (Default an).

### 1.3 Verdrahtung (Koordinator, `src/server/app/compose.ts`)
1. Import: `import { createDraftStore } from '../store/drafts';` und `type FileDraftStore` aus demselben Modul.
2. `interface Stores`: Feld `drafts: FileDraftStore;` (Kommentar: „WP-77 (ADR-210): `entries/<id>/draft.json`“).
3. `openStores`: nach `attachments`
   `const drafts = createDraftStore({ home, warnings });`
   `opened.push({ name: 'drafts', close: () => drafts.close() });`
   und `drafts` im zurückgegebenen Objekt.
4. `createSessionManager({ … stores: { …, attachments: stores.attachments, drafts: stores.drafts } })`.
5. Reihenfolge beim Beenden bleibt: `manager.shutdown()` (flusht) vor `stores.close()` (flusht erneut, sperrt dann).

## 2. Web (`src/web/features/composer/**`)
- `state/drafts.ts`: `setDraft`/`clearDraft` sind Änderungen dieses Fensters und melden sich über
  `connectDraftSync` (kein Import-Zyklus), `replaceDraft` übernimmt einen Server-Entwurf ohne Rückmeldung,
  `resetDraftStore` vergisst auch den Sync-Zustand (Tests).
- `state/draft-sync.ts`: `useDraftSync(sessionKey)` (im Feld montiert), `keepDraftThroughSend`.
  - **Senden:** 400 ms nach der letzten Änderung `session.setDraft` mit dem **erweiterten** Text (`expandPastes`) und
    `pastes`; leeres Feld → `null`; je Session höchstens ein Befehl unterwegs, Änderungen währenddessen folgen danach.
  - **Empfangen:** eigene Stände (`clientId` dieses Fensters, `rev` ≤ höchstem eigenen) werden ignoriert. Ein fremder
    oder gelöschter Entwurf wird nur übernommen, solange das Fenster seit der letzten Bestätigung nichts geändert hat;
    die Chips baut `collapsePastes` (`lib/pastes.ts`) neu (längere Pastes zuerst, Ids nach erstem Vorkommen, Token
    aus `composer.pastes.token`). Gleicher Inhalt → nur bestätigen, das Feld bleibt.
  - **Ack vor Echo:** Ops werden je Frame angewandt, das Ack sofort. Nach einem Ack gilt eine ältere Ansicht nicht als
    fremd, bis die Ansicht den bestätigten Stand (oder einen neueren `rev`) zeigt.
  - **`localStorage`:** Text und Pastes wie bisher; dazu `parallax.composer.draftSync.<sessionKey>` = `dirty`
    (unbestätigt → nach Reload, Wiederverbinden oder erneutem Montieren an den Server) bzw. `clean`. Ohne Marke und
    mit lokalem Text: einmalige Übernahme, wenn der Server keinen Entwurf hat (Migration); sonst gilt der Server.
  - **Fehler** (offline, `NOT_IMPLEMENTED`, `DRAFT_TOO_LARGE`, Validierung) stören nie: kein Hinweis, der Entwurf
    bleibt lokal und `dirty`, die nächste Änderung oder das Wiederverbinden sendet erneut. `NOT_IMPLEMENTED` (älterer
    Server) stoppt das Senden bis zum nächsten Wiederverbinden.
  - Anhänge wandern nicht mit.
- `ContextGauge`: nach „Jetzt komprimieren“ (`/compact`) `keepDraftThroughSend` – der Entwurf geht sofort hinter dem
  Prompt erneut an den Server, so löscht das Senden ihn nicht (der Server verarbeitet Befehle in Eingangsreihenfolge
  synchron bis zum ersten `await`; `sendPrompt` merkt sich den Entwurf davor).
- `src/web/state/fake-host.ts`: nur `session.setDraft` wie die Engine (`detail.patch`, `hasDraft`, `rev` zählt weiter,
  `DRAFT_TOO_LARGE`, `ENTRY_NOT_FOUND`).

## 3. Entscheidungen
1. **`rev` zählt je Serverlauf monoton weiter, auch über einen gelöschten Entwurf** (Start: geladener `rev`). So
   erkennt ein Fenster einen älteren Stand an der Zahl (Ack vor Echo).
2. **Nur `session.sendPrompt` löscht im Server** – nicht `decision.respond`, Seitenfragen, `/rename`, Plan-Freigabe
   oder „Weiter“. Diese Wege senden nicht den Entwurf (bzw. kommen aus anderen Karten); der Composer leert dort lokal
   und schickt `null`. Gelöscht wird nur, wenn sich der Entwurf seit dem Eingang nicht geändert hat.
3. **Store als eigene Umsetzung ohne `.bak`**, Draft-Store in `EngineStores` (wie die anderen Stores), nicht als
   eigenes Manager-Feld.
