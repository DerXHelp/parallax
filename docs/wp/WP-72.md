# WP-72 – Fremde Nachrichten im Transkript zugeklappt und mit Herkunft

Branch `feature/foreign-messages` von `main` (`09d3b7b`). Koordinator direkt (kleiner Umfang, keine Subagenten).
Nutzer-Feedback 16.11.2026, Entscheidungen: Beschriftung „mit Herkunft“, Platz „eigene zugeklappte Zeile“.

## 0. Ausgangslage

**Nutzer:** „Beim Benutzen von Parallax ist mir aufgefallen, dass im Chatverlauf manchmal Nachrichten [stehen], die so
aussehen, als hätte ich sie geschrieben. Unten tragen die ein Badge: ‚Not typed by you (channel, hook or another tool)‘.
Ich möchte, dass die anders dargestellt werden und vielleicht sogar zugeklappt erscheinen. Die stören sonst bei der
Arbeit.“

**Heute:**
- Der Normalizer macht aus jedem `user`-Text ohne `origin.kind 'human'` ein `user_message` mit `origin: 'other'`; die Art
  geht verloren (`live.ts`, `history.ts`).
- Das Transkript zeigt es als normale Sprechblase mit Badge (`items/MessageRows.tsx`).
- Herkunft in den lokalen Claude-Transkripten des Nutzers (`~/.claude/projects/**/*.jsonl`, nur gezählt):
  `task-notification` 905 (meist echte `<task-notification>`-Blöcke → System-Item), `peer` 240, `coordinator` 30, kein
  `channel`. Typische Texte:
  - „Another Claude session sent a message while you were working: `<agent-message from="…">` …“ (`peer`),
  - „The coordinator sent a message while you were working: …“ (`coordinator`),
  - „[SYSTEM NOTIFICATION - NOT USER INPUT] This is an automated background-task event …“ (`task-notification` ohne Block).
- SDK 0.3.322 kennt außerdem `channel`, `observer`, `auto-continuation`, `observer-activity`, `unclassified`.

## 1. Umsetzung

### 1.1 Contract (additiv, freigegeben vom Nutzer)
- `userMessageItemSchema.originKind: z.string().nullable().default(null)`: `origin.kind` bei `origin: 'other'`, sonst
  `null` (auch alte Items). Freier String statt Enum (ADR-198). `sampleItems.userMessage` mit `originKind: null`.

### 1.2 Server
- `normalizer/builders.ts`: `foreignOriginKind(kind)` (null für `human`/fehlend/leer, sonst getrimmt, höchstens
  64 Zeichen); `userMessageItem` setzt `originKind` nur bei `origin: 'other'`.
- `live.ts`, `history.ts`: `originKind: foreignOriginKind(origin?.kind)`.
- Datei-Snapshots neu geschrieben: nur `"originKind": null` kommt hinzu (28 Dateien, 56 Zeilen; die Fixtures enthalten
  keine fremden Nachrichten).

### 1.3 Web
- `UserMessageRow` verteilt: `origin: 'other'` → `ForeignMessageRow`, sonst die bisherige Sprechblase (`OwnMessageRow`,
  Badge „Not typed by you“ entfällt).
- `ForeignMessageRow`: `Disclosure` (zu, Zustand in `state/expansion`), Kopf = Symbol + eine gekürzte Zeile
  „Herkunft · Vorschau“, `text-muted-foreground text-xs` wie Thinking-Zeilen; aufgeklappt eingerückt mit linker Linie,
  `CappedContent` + `UserText` (lange Texte weiter mit „Alle n Zeilen anzeigen“) + Anhänge.
- Herkunft → Symbol/Text: `peer` → `MessagesSquare` „Nachricht einer anderen Session“, `coordinator` → `Network`
  „Nachricht des Koordinators“, `task-notification` → `Bell` „Automatische Meldung“, `channel` → `Radio` „Nachricht aus
  einem Kanal“, sonst `MessageSquareDashed` „Nicht von dir getippt“.
- `lib/text.ts` `foreignPreview`: erste ~4000 Zeichen, ohne Leerzeilen, reine Tag-Zeilen und `[…]`-Banner, eine
  einleitende Zeile mit „:“ entfällt, wenn danach Text kommt; Rückfall erste Zeile.
- i18n `transcript.user.origin.{peer,coordinator,notification,channel,unknown}` (en/de, Start-Chunk; kein Schlüssel
  `other`, der als Pluralform gälte).
- Kompakte Ansicht unverändert: `user_message` bleibt Code `v` (eigene Zeile).
- Playground „Compact transcript (WP-63)“: eine `peer`-Nachricht und eine automatische Meldung.

## 3. Offen / Follow-ups
- `peer.body` (vom SDK entpackter Text) und Absendername (`peer.name`/`from`) könnten die Vorschau verbessern; bräuchte
  weitere Felder (Contract) und im Verlauf eine Port-Änderung (`HistoryMessage.origin` trägt nur `kind`).

- Kein Fake-Hebel für fremde Nachrichten (nur Playground und Unit-Tests); live prüft der Nutzer im Alltag.
