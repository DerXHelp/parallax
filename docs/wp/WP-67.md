## 1. Auftrag

### Pflichtlektüre
`CLAUDE.md`; `docs/wp/SDK-MOEGLICHKEITEN.md` §3; ADR-126, ADR-154, ADR-160; `src/server/backend/{types,sdkBackend}.ts`,

### 1.1 Server
- Ein Host-Befehl **`session.info { entryId, section }`** (lesend) holt die Daten eines Reiters über die laufende
  Session: `status` | `memory` | `skills` | `hooks` | `permissions` | `mcp` | `export`. Antwort normalisiert und
  zod-geprüft (Contract §2). **Nur auf Anfrage** (Reiter öffnen, „Aktualisieren“) – kein Hintergrund-Polling,
  kein Cache über die Dialogdauer hinaus.
- Läuft kein Prozess: `SESSION_NOT_RUNNING` (die UI bietet „Session starten“ an; kein automatisches Wecken nur
  zum Anzeigen). Externe Sessions: `SESSION_EXTERNAL`.
- **Laufzeitprüfung** je Methode: fehlt sie oder passt die Antwort nicht → Ergebnis `{ available: false }` für
  diesen Reiter (kein Fehler-Toast), einmal loggen. Unbekannte Felder ignorieren und zählen.
- **Aktionen:** `session.mcpAction { entryId, server, action: 'reconnect' | 'enable' | 'disable' }` und
  `session.reload { entryId, what: 'skills' | 'plugins' }`; danach liefert der Reiter frische Daten. Fehler als
  `CLAUDE_CONTROL_FAILED`.
- **Export:** Text + vorgeschlagener Dateiname; Speichern über einen Download im Browser (kein Schreiben durch
  den Server in beliebige Pfade).
- **Datenschutz:** Status-Zeilen (Konto/E-Mail) nur an den Client der eigenen Instanz, nie loggen.

### 1.2 UI (en/de, Tokens, Primitives aus `src/web/ui`)
- „Session-Info“ wird ein Dialog mit Reitern: **Übersicht** (heutiger Inhalt) · **MCP** · **Berechtigungen** ·
  **Skills** · **CLAUDE.md** · **Hooks** · **Status** · **Export**. Größer als heute (breiter, scrollbar), im
  schmalen Fenster Reiter als Auswahlliste. Letzter Reiter je Fenster gemerkt (localStorage, try/catch).
- Je Reiter: Ladezustand, „Aktualisieren“, leerer Zustand, „nicht verfügbar mit dieser `claude`-Version“,
  „Session läuft nicht – starten?“.
- **MCP:** Liste mit Status (bestehende Übersetzungen `navigation.info.mcpStatus.*`), Knöpfe „Neu verbinden“,
  „An/Aus“ (mit Bestätigung bei „Aus“). Fehlerdetails, wenn das CLI sie liefert.
- **Berechtigungen:** gruppiert nach Erlauben/Fragen/Verbieten und Quelle (Benutzer, Projekt, lokal, Session,
  Startargumente); Arbeitsordner. Suchfeld.
- **Skills:** Tabelle Name, Quelle, Token-Schätzung, Zustand (gesperrt durch …), Summe der Tokens; „Skills neu
  laden“, „Plugins neu laden“. Sortierbar nach Tokens.
- **CLAUDE.md:** Dateien mit Ebene (Benutzer/Projekt/lokal/eingebunden), Pfad als `FileLink` (Viewer/Editor
  über den vorhandenen Datei-Dienst, nur innerhalb der erlaubten Wurzeln; sonst Pfad kopieren), Schalter nur
  anzeigen.
- **Hooks:** nach Ereignis und Matcher, Befehl als Code (monospace, Steuerzeichen so, wie das CLI sie liefert);
  Hinweis bei Policy/Safe-Mode.
- **Status:** die Zeilen des CLI als Liste (Werte sind schon Text).
- **Export:** Vorschau (die ersten Zeilen), „Kopieren“, „Speichern“ (Download mit dem vorgeschlagenen Namen).
