# WP-111 – Server: Git-Dienst, Worktrees, Setup/Teardown/Ports, Review-Store, Diff-Basis

Auftrag: `docs/wp/WP-110.md` §3.1–3.5, §6 und §8.1 (Zeilen „111“), Branch `wp/111` (von `feature/ausbau-1`),
21.11.2026. Grundlage: Contracts v5 (ADR-250…254), unverändert bis auf die eine additive Port-Ergänzung in §3.

## 1. Ergebnis

### 1.1 Git-Dienst (`src/server/git/`)

| Datei | Inhalt |
|---|---|
| `runner.ts` | `createGitRunner()` – der einzige Weg zu `git`: absoluter Pfad über `resolveExecutable` auf dem PATH der Session (eine Minute je PATH gemerkt), `runFile` mit Argument-Array, `--no-pager`; lesend zusätzlich `-c core.fsmonitor=false` und `GIT_OPTIONAL_LOCKS=0`; immer `GIT_TERMINAL_PROMPT=0`, `LANGUAGE=en`, ohne `GIT_DIR`/`GIT_WORK_TREE`/… (Namen nach den Regeln der Plattform). Zeitgrenzen 10 s (lesen) bzw. 120 s (schreiben), Ausgabegrenze je Strom mit `truncated`. Fehler: `GIT_NOT_FOUND`, `NOT_A_GIT_REPO {path}`, `GIT_FAILED {op, exitCode?, detail?}` (erste Zeile, Zugangsdaten in URLs entfernt, ≤ 300 Zeichen). Ausgaben werden nie protokolliert. |
| `parse.ts` | Reine Parser der `-z`-Ausgaben: `status --porcelain=v2`, `diff --raw --numstat`, `worktree list --porcelain`, Patch-Körper, Push-Fehlergrund; Ordner von git in Host-Schreibweise (`hostPath`, `rootInCwdSpelling`). |
| `repo.ts` | Operationen: Status, Diff-Liste und Datei-Diff (Bereiche `session`/`uncommitted`/`staged`), Commit, Branch anlegen/wechseln, Push, Worktree anlegen/auflisten/prüfen/entfernen, Branch löschen, `info/exclude`, `.worktreeinclude`. |
| `commands.ts` | `createGitCommands(deps)` – die Host-Befehle `git.*` und `worktree.*`; `sessionDiffBase` (ADR-253). Ohne `deps` (Aufruf des Gerüsts in `compose.ts`) `NOT_IMPLEMENTED`. |
| `testRepo.ts` | Testhelfer: echte Repositories unter dem Test-Home, git ohne globale/System-Konfiguration, feste Autorenschaft `*.example`. |

- **Diffs:** `--no-color --no-ext-diff --no-textconv --no-relative -M`, Pfade immer nach `--`. Untracked-Dateien
  (`ls-files --others --exclude-standard`) zählen im Bereich `session` und `uncommitted` als „hinzugefügt“: `lstat`,
  nur reguläre Dateien, NUL in den ersten 8000 Bytes = binär, Inhalt höchstens `LIMITS.gitPatchBytes`, zusammen
  höchstens 32 MiB je Liste; der Patch (`@@ -0,0 +1,N @@`) entsteht ohne git. Ohne Commit vergleicht `session` mit
  dem leeren Baum (SHA-1 oder SHA-256 nach `rev-parse --show-object-format`).
- **`git.diff {onlySessionFiles}`** behält die Dateien aus `files.session` (Vergleich der absoluten Pfade nach den
  Regeln des Rechners, bei Umbenennungen auch der alte Pfad); ohne Antwort des Datei-Dienstes kein Filter.
- **`git.commit`** prüft `paths` gegen die Wurzel (`VALIDATION_FAILED {field: 'paths', reason: 'outside'}`), danach
  sofort `Entry.gitBranch` neu (`headChanged`); ebenso nach `git.branchSwitch`/`git.branchCreate {switch}`.
- **`git.push`** ohne Remote oder im Detached HEAD `GIT_PUSH_FAILED {reason: 'other'}`; ohne Upstream mit
  `-u <remote> <branch>` (`origin`, sonst das einzige Remote); Gründe `auth`/`rejected`/`network`/`other` aus der englischen Meldung, Zeitüberschreitung =
  `network`.

### 1.2 Diff-Basis (ADR-253)
`session.create` merkt `Entry.baseSha` = HEAD des `cwd` (ohne Ordner oder ohne git `null`, ohne Rückfrage an
`claude`). Worktree-Sessions vergleichen mit dem Merge-Base von `worktree.baseRef` und HEAD (ist `baseRef` weg:
`worktree.baseSha`). Alte Einträge ohne `baseSha` bekommen beim ersten `session`-Diff den aktuellen HEAD und behalten
ihn; eine gespeicherte Basis, die es nicht mehr gibt, ersetzt der aktuelle HEAD nur für diesen Aufruf.

### 1.3 Worktrees (ADR-250), `src/server/sessions/worktrees.ts`
- **Neu:** Synchron vor dem Eintrag (eine Ablehnung legt nichts an): Repository (`NOT_A_GIT_REPO`), Basis
  (`baseRef`, sonst der aktuelle Branch des Haupt-Worktrees, sonst `HEAD`; `VALIDATION_FAILED {field:
  'worktree.baseRef'}`), Branch (`BRANCH_EXISTS`), Ordner `<repo>/.claude/worktrees/<branch, / → ->`
  (`WORKTREE_EXISTS`; parallele Anlagen sperrt eine Liste im Speicher), Portblock. Danach entsteht der Eintrag mit
  `cwd` = Worktree-Ordner und `worktreeSetup: creating`, Ack mit `messageUuid: null`. Asynchron: `git worktree add -b`,
  `/.claude/worktrees/` in `info/exclude` des gemeinsamen git-Ordners, `.worktreeinclude` kopieren, Setup.
- **`.worktreeinclude`:** Kandidaten über `ls-files --others --ignored --exclude-from=<datei>`, davon nur die von git
  ignorierten (`--literal-pathspecs ls-files … --exclude-standard`), ohne `.claude/worktrees/`; Kopie mit
  `COPYFILE_EXCL`, nur reguläre Dateien, höchstens 2000 Dateien bzw. 512 MiB.
- **Vorhanden:** ein Worktree aus `worktree.list` (kein Anlegen, kein Setup); den Portblock übernimmt er von einem
  Eintrag im selben Ordner.
- **Start-Prompt:** wartet in `heldStart` bis zum Exit 0 des Setups (dann `startRuntime` + `deliverPrompt`). Während
  `creating`/`setup` antworten Prompt, Fortsetzen, Entscheidungen usw. mit `SESSION_BUSY {reason: 'worktree_setup'}`.
  Bei `failed` startet `session.resume`/`session.sendPrompt` trotzdem („Trotzdem starten“) und schickt den
  gehaltenen Prompt zuerst. Scheitert `git worktree add`, steht `failed` plus ein System-Fehler im Transkript.
- **`worktree.list`/`worktree.inspect`/`worktree.remove`:** `inspect` liefert offene Dateien, ungepushte Commits und
  ob der Branch in der Basis enthalten ist. `remove` läuft in der Lebenszyklus-Sperre: nicht während die Session
  läuft (`SESSION_BUSY`); offene Arbeit ohne `force` → `WORKTREE_DIRTY {dirtyFiles, unpushedCommits}` (ungepushte
  Commits zählen nur mit `deleteBranch`); Teardown (außer `skipTeardown`, Exit ≠ 0 → `GIT_FAILED {op: 'teardown',
  exitCode}`); Terminals des Eintrags schließen (`closeEntry`), HEAD-Beobachtung beenden, `git worktree remove
  [--force]` (fehlt der Ordner: `prune`), Eintrag `worktree: null`, dann `git branch -d` bzw. `-D` (bei `force` oder
  ohne ungepushte Commits).

### 1.4 Setup, Teardown, Ports (ADR-251)
- **`runScript`** im Terminal-Dienst: sichtbarer Tab (Titel `Setup`/`Teardown`), Shell des Projekts, Exit-Code als
  Promise. cmd wörtlich `"<cmd.exe>" /d /s /c "<befehl>"` (Zeilen mit ` && ` verbunden), PowerShell `-NoLogo -Command`,
  Git Bash `--login -c`, POSIX Login-Argumente und `-c` (pwsh `-Command`). Auch für archivierte Einträge
  (Teardown vor dem Entfernen). Der Vermittler startet ihn mit `origin: 'remote'` (`peerTerminal.ts` war schon fertig;
  die Engine nimmt `remote`, sobald das Fenster nicht `local` ist).
- **Portblock:** nur mit `settings.projects[repoRoot].ports`; erster freier 10er-Block ab 41000 bis 49990 (keine
  `portBase` eines anderen Eintrags, alle zehn Ports auf 127.0.0.1 frei), gespeichert in `WorktreeRef.portBase`.
- **`PARALLAX_WORKTREE_PORT`:** `buildEnv` Schritt 4 (`BuildEnvInput.worktreePort`, `worktreePortEnv`), Setup/Teardown
  (`spec.env`), Terminals des Eintrags (`TerminalServiceOptions.entryEnv`), Claude-Prozesse und externe Konsole über
  den Dekorator `withWorktreePort(claude, portOf)`. Die beiden letzten verdrahtet der Koordinator in `compose.ts`
  (§4).
- Ohne Projekteinstellungen passiert nichts davon.

### 1.5 Review-Store (ADR-254)
- `src/server/store/review.ts`: **`createReviewStore({home, warnings, …}): FileReviewStore`** (Port `ReviewStore`
  plus `close()`), Datei `entries/<id>/review.json`, Schreiben entprellt und atomar, kaputte Datei in Quarantäne,
  zu neue Version sperrt das Schreiben, leere Liste löscht die Datei.
- `src/server/sessions/review.ts`: `review.add` (ID `rc_…` und Zeit vom Server, höchstens
  `LIMITS.reviewCommentsMax`), `review.update` (nur angegebene Felder, `endLine ≥ line`, ohne Änderung keine Op),
  `review.remove`, `review.markSent`. Jede Änderung als Op `review.upsert`/`review.remove`; die geladene Ansicht
  (`detail.review`) liest die Liste beim Aufbau des Spiegels. `session.remove` löscht die Datei.

### 1.6 HEAD-Beobachtung
`watchGitHead` (`sessions/lib/gitBranch.ts`): `rev-parse --absolute-git-dir`, `fs.watch` ohne `persistent` auf den
git-Ordner (bei verknüpften Worktrees `.git/worktrees/<name>`), nur `HEAD`/`HEAD.lock`, 150 ms entprellt, höchstens 64
gleichzeitig. `EntryState` startet sie nach einem erfolgreichen Branch-Lesen für Einträge im Repository und beendet
sie beim Entfernen, beim Herunterfahren und wenn kein Branch mehr da ist. Ein `git switch` im Terminal erscheint
damit sofort in der Kopfzeile.

### 1.7 Weg der Befehle
`git.*`, `worktree.*` und `review.*` fängt `sessions/commands.ts` (`hostCommand`) ab und reicht sie an
`handleGitCommand` bzw. `handleReviewCommand` mit dem Engine-Zustand weiter. Für Sessions anderer Rechner leitet der
Vermittler die Host-Befehle wie alle anderen weiter.

## 2. Entscheidungen
1. **Abfangen in der Engine statt eigener Handler in `compose.ts`:** Git- und Review-Befehle brauchen Einträge,
   Lebenszyklus-Sperre, Terminals und Stores der Engine. Die Gerüst-Handler aus `compose.ts` sind damit unerreichbar.
2. **Port-Variable über Dekoratoren/Optionen statt Änderungen in `runtime.ts`/`manager.ts`:** `withWorktreePort` und
   `entryEnv` halten WP-111 in seinen Pfaden; die Verdrahtung ist eine Zeile je Stelle in `compose.ts`.
3. **cmd-Befehlszeile wörtlich:** `cmd /s /c "<befehl>"` lässt sich mit den Quoting-Regeln von `conPtyCommandLine` nicht
   ausdrücken (Anführungszeichen im Befehl); daher das optionale Feld `PtySpawnOptions.windowsCommandLine` (§3).

## 3. Schnittstellen/Contract-Abweichungen
- `src/server/terminal/ports.ts`: **neu, optional** `PtySpawnOptions.windowsCommandLine?: string` – fertige
  Windows-Befehlszeile, die `conpty.ts` statt der aus `file`/`args` gebauten nimmt (nur `runScript` mit cmd).
  Bestehende Felder unverändert.
- Sonst keine Änderung an `src/shared/**` oder Ports. Additive Exporte in eigenen Dateien: `BuildEnvInput.worktreePort`,
  `WORKTREE_PORT_ENV`, `worktreePortEnv` (`claude/env.ts`), `TerminalServiceOptions.entryEnv` (`terminal/service.ts`),
  `EngineStores.review` (`sessions/entryState.ts`, optional).

  Speicher, der Store hat eigene Tests.

## 5. Stolpersteine
- **Heredocs im Bash-Werkzeug halbieren Backslashes** (`'C:\\x'` wurde `'C:\x'`, `\\n` ein Zeilenumbruch). Dateien mit
  Backslashes nur mit Write/Edit oder einem per Write abgelegten Skript schreiben.
- `git check-ignore -z` verlangt `--stdin`; stattdessen `ls-files --others --ignored --exclude-standard -- <pfade>`
  mit `--literal-pathspecs`.
- Ein Worktree auf einem Commit vor der `.gitignore` zeigt kopierte `.worktreeinclude`-Dateien als offen – in Tests den
  Worktree auf den Commit mit der `.gitignore` setzen.
- `setEnvVar` ersetzt unter Windows eine vorhandene Schreibweise (`git_terminal_prompt` → `GIT_TERMINAL_PROMPT`).
- Die Engine-Testumgebung nutzt einen `cwd`, den es nicht gibt; `sessionBaseSha` prüft deshalb zuerst den Ordner und
  ruft dann weder git noch die Startkonfiguration.

## 6. Offen (Follow-ups)
- Der Composer sollte während `worktreeSetup` (`creating`/`setup`) gesperrt sein (WP-114/WP-117); der Server antwortet
  mit `SESSION_BUSY {reason: 'worktree_setup'}`.
- Ein gehaltener Start-Prompt geht bei einem Neustart des Servers mitten im Setup verloren (nur im Speicher); der
  Eintrag zeigt dann keinen Setup-Zustand mehr und startet normal.
- Die Tab-Titel `Setup`/`Teardown` sind Server-Texte (nicht übersetzt), wie andere Terminal-Titel.
