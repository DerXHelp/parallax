## Befunde

Schweregrade: **[BLOCKER]** vor dem Phase-1-Abschluss zwingend · **[SOLLTE]** in der Fix-Runde ·
**[NIT]** bei Gelegenheit.

**WP22-01 [SOLLTE] Modell vor dem ersten Prompt nicht wählbar.** *Modul:* WP-13b
(`sessions/commands.ts` `refreshModels`: ohne laufenden Prozess und ohne Katalog
`SESSION_NOT_RUNNING`), WP-16 (`composer/ModelPicker.tsx`). Der Picker zeigt bis zum ersten Start
nur „The model list is available while the session runs.“ Der erste Turn läuft deshalb immer mit dem
CLI-/Nutzer-Default – hier `model: "opus"`, `effortLevel: "xhigh"` (teuer). Nur `ANTHROPIC_MODEL` in
der Server-Umgebung half. *Vorschlag:* Katalog je Profil persistieren (`core.setModels` nach dem
ersten Start in einen Store) und/oder statische Aliase (`default`, `opus`, `sonnet`, `haiku`) als
Fallback anbieten; `session.create` mit `model` nutzt der Dialog bisher nicht.

**WP22-02 [SOLLTE] KI-Titel wird nie übernommen.** *Modul:* WP-13b (`sessions/summary.ts`
`aiTitleFrom`, Z. 137), ggf. WP-13c (`backend/history/parse.ts`). Mit SDK 0.3.296/CLI 2.1.300 liefert
`getSessionInfo()` den KI-Titel als **`customTitle`** (Beleg: Session ohne `/rename` →
`{summary: "Datei test.txt erstellen", customTitle: "Datei test.txt erstellen", firstPrompt: "lege
test.txt …"}`; Transkript nur `ai-title`-Einträge, `<session>\custom-title.json` von der CLI). Die
Regel „`customTitle !== null` → nicht übernehmen“ verwirft ihn; der Eintrag behält den Prompt-Titel
(`titleSource: prompt`, im Hauptlauf und im Live-Smoke). Fehler bei `getSessionInfo` loggt der Manager
nur auf `debug`. *Vorschlag:* eigene Titel nur über `system/session_title_changed` nach `/rename`
bzw. `session.rename` erkennen (der Server weiß, was er gesetzt hat), sonst `summary` übernehmen;
Test mit dem echten Feldbild.

**WP22-03 [SOLLTE] Benachrichtigungen lassen sich im Edge-App-Fenster nicht aktivieren.** *Modul:*
