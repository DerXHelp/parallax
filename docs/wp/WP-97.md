# WP-97 – Shell im Projektordner öffnen (Stufe 1 von WP-97…99)

Koordinator, Branch `feature/konsole`. Auftrag des Nutzers am 20.11.2026.

## Auftrag
„In dem Verzeichnis, in dem ich Claude Code starte, habe ich häufig Bedarf, cmd oder Git Bash zu starten. […]
Trivial wären Knöpfe, um die Konsolen zu starten, aber cool wäre natürlich, wenn ich das vielleicht auch direkt in
Parallax machen könnte. Auf ‚Remote Sessions‘ sollte das erstmal nicht möglich sein.“

**Entscheidungen des Nutzers (Planung 20.11.2026):**
- Beide Stufen planen und nacheinander umsetzen:
  - **Stufe 1 (WP-97):** Shell als eigenes Fenster.
  - **WP-98:** Spike zur ConPTY-Anbindung.
  - **WP-99:** eingebettetes Terminal als Tab im Seitenpanel, eigene ConPTY-Anbindung über `node:ffi`.
- Git Bash startet standardmäßig als **mintty**.
- Umgebung **neutral**: ohne Profil-Env und ohne `CLAUDE_CONFIG_DIR`.

## Umsetzung (ADR-238)

### Contract (additiv, `PROTOCOL_VERSION` bleibt 6)
- `model.ts`:
  - `SHELL_KINDS`/`shellKindSchema` (`cmd`, `powershell`, `gitbash`) und `GIT_BASH_WINDOWS`/`gitBashWindowSchema`
    (`mintty`, `terminal`).
  - `consoleSettingsSchema {defaultShell, gitBashWindow, gitDir}`. `gitDir` muss ein sicherer Pfad sein oder null.
  - Settings-Feld `console` mit Default `DEFAULT_CONSOLE_SETTINGS` (`cmd`, `mintty`, `null`).
- `protocol.ts`:
  - Host-Befehle `session.openShell {entryId, shell}` → `{pid}` und `shell.detect` → `{gitDir}`.
  - Beide stehen in `REMOTE_DENIED_COMMANDS`.
- `errors.ts`: `SHELL_NOT_FOUND {shell}` (setup/503) und `SHELL_OPEN_FAILED {reason}` (500, wiederholbar).

### Server: `src/server/terminal/` (README dort)
- `shells.ts`:
  - Neutrale Umgebung (`guiEnvironment` + PATH ohne `node_modules\.bin`).
  - Git-Suche mit Cache von einer Minute, Reihenfolge:
    1. Einstellung
    2. `%ProgramFiles%\Git`
    3. `%LOCALAPPDATA%\Programs\Git`
    4. `git.exe` auf PATH
    5. `Git_is1`
  - `resolveShellLaunch` je Shell und Modus (`window`, `embedded` für WP-99).
- `shellCommands.ts`:
  - Ablauf: Eintrag holen, dann `checkCwd`, `resolveShellLaunch`, `ConsoleLauncher.open`.
  - Fehler werden bereinigt (`scrubConsoleReason`).
  - Mit dem FakeBackend nimmt `createRecordingShellLauncher` den Aufruf auf und loggt
    `session.openShell (fake): …`.
- Komposition: `createShellCommands` steht in `hostCommands` (`app/compose.ts`).

### Web
- **Menüs** (`session-actions.tsx`):
  - Aktion `openShell` als Untermenü in beiden Session-Menüs, nach „Ordner im Explorer öffnen“.
  - `SessionAction.children` und `SessionSubAction` sind neu; `SessionActionItems` rendert sie mit den Radix-Sub-Menüs.
  - Die Standard-Shell trägt „Standard“ und Alt+K.
  - Über `ACTION_COMMANDS.openShell` blendet `sessionAllows` die Aktion für Sessions eines anderen Rechners aus.
- **Kopfzeile:** `navigation/ConsoleButton.tsx` ist ein Split-Knopf.
  - Das Icon öffnet die Standard-Shell.
  - Der Pfeil zeigt cmd, PowerShell, Git Bash und „Konsolen-Einstellungen…“.
  - Nur in breiter Kopfzeile und nur, wenn `sessionAllows(sessionKey, 'session.openShell')`.
- **Alt+K** (`NavigationLayer.tsx`, wie F2): Es gilt die Zeile mit Fokus, sonst die gewählte Session. Das Kürzel
  wirkt auch im Textfeld.
- **Einstellungen**, Abschnitt „Konsole“ (`features/preferences/sections/ConsoleSection.tsx`, nach „Dateien“):
  - Radiogruppen für Standard-Shell und Git-Bash-Fenster, beide speichern sofort.
  - Ein Feld für den Git-Ordner: gespeichert bei Enter oder beim Verlassen, unsichere Pfade lehnt es mit Hinweis ab,
    leer heißt „gefunden“.
  - Eine Zeile „Git Bash gefunden: …“ über `shell.detect`.
  - Ein Hinweis zur neutralen Umgebung.
- Fake-Host (Playground): `session.openShell` → `{pid: null}`, `shell.detect` → `C:\Program Files\Git`.

## Offen / Stolpersteine
- Zwei Annahmen sind nicht automatisiert geprüft, sie kommen in die manuelle Prüfung mit dem echten Launcher:
  - dass `git-bash.exe` ein gequotetes `--cd=` versteht (so macht es auch Git selbst im Explorer-Menü);
  - dass `bin\bash.exe` `CHERE_INVOKING=1` braucht, um im `cwd` zu bleiben.
- In happy-dom öffnet ein Mausklick ein Radix-Untermenü nicht zuverlässig, weil die Zeiger-Toleranzzone Geometrie
  braucht. Die Tests steuern das Untermenü deshalb per Tastatur.
