### Anforderungen (normativ)
1. **`outputFile`:** aus `task_notification.output_file` und `AgentOutput.outputFile`
   (Tool-Ergebnis) in `tool_call.task.outputFile` bzw. das System-Item; `''` → `null`; gilt für
   Live und Verlauf.
2. **`session_writes_lost`:** System-Item `event:'error'` mit
   `error: {code:'SESSION_WRITES_LOST', params:{lost, errorCode}}`; unbekannte Felder tolerant.
3. **Context-`id`:** `normalizer/context.ts` übernimmt die `id` der SDK-Kategorie (fehlt → `null`),
   Zuordnung „ist frei/Puffer/…“ zuerst über `id`, dann wie bisher über den Namen.
4. **`sdkOptions.ts`:** `perTaskStopAffordance: true`, `agentProgressSummaries: true`;
   `additionalDirectories` = Profil-Ordner + `attachmentsDir` (ohne Duplikate per
   `windowsPathsEqual`); `todoFeatureEnabled: true` als Flag-Setting (in `startFlagSettings`, also
   auch bei Profilen mit Settings-Datei über `applyFlagSettings`); Tabellen-Tests ergänzen, Kopfkommentar
   („Deliberately NOT set …“) anpassen.
5. **`sdkBackend.ts`:** `inlinePastes` → `SDKUserMessage.inline_pastes` (nur wenn nicht leer);
   `document`-Blöcke wie bisher; kein `client_composed`.
6. **FakeBackend** (`fake/session.ts`, `fake/interactive.ts`, neue Szenario-Dateien; nur `.ts`,
   jedes Event besteht `fixtureEventSchema` und den echten Normalizer):
   - `stopTask(taskId)` beendet eine laufende Fake-Task mit `task_notification` `stopped`;
     unbekannt → Fehler wie das SDK.
   - `fake:plan` erweitert: Plan-Modus schreibt die Plan-Datei per `Write` mit gestreamtem Input
     (`input_json_delta` in ≥ 5 Teilen), **echte** Datei unter
     `%TEMP%\parallax-fake-files\<sessionId>\plans\<name>.md`, danach `ExitPlanMode` mit
     `planFilePath`; nach einem Feedback-`deny` v2 mit geändertem Text in dieselbe Datei.
   - `fake:background`: Hintergrund-Agent (`run_in_background`) mit `task_started`,
     `task_progress` (mit `summary`), `background_tasks_changed`, nach 30 s `task_notification`
     `completed` mit `output_file` (echte Datei im Fake-Ordner); per `stopTask` vorher beendbar.
   - `fake:todo`: `TodoWrite` mit drei Punkten, danach Status-Updates (ein `in_progress`, dann
     `completed`).
   - `fake:files`: `Read`, `Write`, `Edit` auf echte Dateien im Fake-Ordner (vorher angelegt) und eine
     Antwort mit Verweisen (`<pfad>:12`, relativer Pfad, Markdown-Link, ein UNC-Pfad
     `\\fake-host\share\x.txt` als Negativfall).
   - `fake:writes-lost`: `system/session_writes_lost` beim Beenden.
   - Prompts mit PDF-/`document`-Blöcken bzw. `Attached files:`-Block → Antwort „Fake: received N
     document(s), M file(s)“; `inline_pastes` → „Fake: received K paste(s)“.
   - Start ohne Resume mit erstem Prompt `Implement the following approved plan.` → Antwort „Fake:
     implementing plan (N lines)“; `init.permissionMode` = Start-Modus.
   - Echte Dateien schreibt der Fake **nur** unter `%TEMP%\parallax-fake-files\`, nie ins Projekt.
7. **`FAKE_MODELS`** (`fake/defaults.ts`): Stand CLI 2.1.322 (14 Einträge inkl. `fable`, Quelle
   `SDK-0.3.322.md` §5.8); Fake-Kategorien von `getContextUsage` mit `id`.
8. README von `backend/fake/` um die neuen Schlüsselwörter ergänzen.
