### Anforderungen (normativ)
1. **Store (ADR-102):** `JsonStore` mit `profilesFileSchema` (v1), `backup`, Warnungen; fehlt die
   Datei → nur `STANDARD_PROFILE` im Speicher, geschrieben erst beim ersten `save`/`setDefault`.
   Fehlt „Standard“ in der Datei → ergänzt. Genau ein `isDefault` (mehrere/keiner → erster bzw.
   „Standard“, Warnung ins Log). `save`: neue ID `pf_` + 32 Hex (`lib/ids.newId`), `createdAt`/
   `updatedAt` vom Server, `builtin` nur für `standard`; Fehler-Issues → `PROFILE_INVALID{count}`.
   `remove`: `builtin` → `PROFILE_NOT_DELETABLE`; war Default → „Standard“ wird Default.
   Profil-Env-Werte mit geheimen Schlüsselnamen (`*_KEY`, `*_TOKEN`, `*_SECRET`, `*PASSWORD*`,
   case-insensitiv) beim Laden/Speichern per `registerSecret` maskieren (R9).
2. **Issues (`ProfileIssue = {level, issue}`, WP-30 §4.5):** `profileIssues` liefert
   - `level 'error'`: die `errors` von `parseProfileArgs(args, passRawArgs)` (`PROFILE_ARG_BLOCKED`,
     `PROFILE_ARG_NOT_ALLOWED`, `PROFILE_ARG_INVALID` mit `ProfileArgIssueParams`);
     `executable.path` nicht absolut / kein `.exe` / `windowsPathIssue` ≠ null / Datei fehlt →
     `PROFILE_INVALID{field:'executable', reason:'not_absolute'|'not_exe'|'unsafe'|'not_found'}`;
     `configDir` mit `windowsPathIssue` ≠ null → `PROFILE_INVALID{field:'configDir', reason:'unsafe'}`;
   - `level 'warning'`: die `warnings` von `parseProfileArgs` mit Schweregrad warning
     (`PROFILE_ARG_BROAD_ALLOWED_TOOLS`, `PROFILE_BYPASS_ENABLED`, `PROFILE_ARG_RESUME_NO_EFFECT`) und
     unaufgelöste `${env:NAME}` (`PROFILE_ENV_REF_UNRESOLVED{name,key}`);
   - `level 'info'`: `PROFILE_ARG_PASSED_RAW`.
   Ein fehlender `configDir`-Ordner ist kein Befund (die CLI legt ihn beim Login an).
3. **Summaries:** `ProfileSummary.{defaults, configDir, issues}`; `entryCount` bleibt 0 (füllt die
   Engine, WP-31).
4. **Befehle (`createProfileCommands`, §4.12):** `profile.get` (vollständiges `Profile` inkl. Env,
   Issues, `entryCount`), `profile.save` (→ `{profileId}`), `profile.delete` (`entryCount > 0` →
   `PROFILE_IN_USE{count}`), `profile.setDefault`, `profile.test` (`integration.checkProfile`, Ergebnis
   landet im Store → `onChange`), `profile.validate` (nur Issues, kein Schreiben). Ergebnisse passen
   zu `commandResultSchemas`.
5. **Integration:** nutzt den übergebenen Store; bei `onChange` je Profil die Auflösungs-Caches
   verwerfen. `consoleLaunchFor(req)`: Profil laden, Fehler-Issues → `PROFILE_INVALID`; ausführbare
   Datei wie `launchSpecFor`; `env` = `buildEnv(target 'terminal', entryId)`; `explicitEnv` = aufgelöste
   Profil-Env + `CLAUDE_CONFIG_DIR` (falls gesetzt); `args` = `profile.args` (unverändert, bereits
   geprüft) + `--resume <id>`; zusätzlich `--model <model>` bzw. `--permission-mode <mode>`, wenn
   gesetzt und nicht schon in den Args; `--settings {"autoCompactWindow":N}` bei `contextWindow`,
   wenn die Args kein `--settings` haben (sonst Warnung ins Log); `cwd` exakt.
6. **`consoleCommandText`:** `Set-Location -LiteralPath '<cwd>'; $env:NAME='<wert>'; …; & '<exe>' <args>`
   mit PowerShell-Quoting (einfache Anführungszeichen, `'` verdoppelt), Args einzeln gequotet;
   tabellengetestet (Leerzeichen, `'`, `$`, `` ` ``, Umlaute, leere Args).
7. **Preflight:** `scripts/preflight.ts` lädt die Profile des Datenordners **nur lesend**
   (`PARALLAX_HOME` bzw. `defaultHome()`, `profilesFileSchema`; neuere Version → `warn`, ohne Datei →
   nur „Standard“) und prüft jedes Profil (`runPreflight` schleift schon). Kein Schreiben.
