### Entscheidung CR5 (Contract-Ergänzung, additiv)

`WorktreeRef.removedAt` (`isoDateTimeSchema.nullable().default(null)`, ältere Dateien und Hosts lesen `null`) und der
Helfer `liveWorktree(ref)` in `src/shared/model.ts`. `worktree.remove` behält den Datensatz und setzt `removedAt`, statt
`worktree: null` zu schreiben. Damit bleibt die Session in der Gruppe ihres Repos (`sessionProjectPath`, Projekt im
Notifier, bekannte Projektwurzeln), obwohl `cwd` auf den gelöschten Ordner zeigt. Alles, was den Worktree selbst braucht,
nimmt `liveWorktree`: Port-Block und `PARALLAX_WORKTREE_PORT`, gemeinsamer Ordner im Modus „existing“, `worktree.inspect`
und `worktree.remove` (danach `VALIDATION_FAILED`), Diff-Basis der git-Befehle, Aufräum-Dialog (`wantsCleanup`,
Archivieren/Entfernen im Session-Menü), Branch-Zeile und Worktree-Hinweis in der Sidebar, Filter „nur Session-Dateien“
im Tab Änderungen.

### Abweichungen und Hinweise

- CR10: `git worktree add` läuft jetzt synchron in `session.create`. Das Zeitlimit des Clients für Befehle (60 s) ist
  kürzer als das von git (120 s); bei sehr großen Repos kann der Client vor dem Server aufgeben. Der Eintrag entsteht
  dann trotzdem und erscheint per Op.
- CR6: PowerShell und fish prüfen je Zeile, eine Zeile muss also eine vollständige Anweisung sein (mehrzeilige Blöcke
  dort nicht unterstützt). Eine Login-Shell der csh-Familie bekommt kein `set -e`.
- SR1: `git config --show-scope` braucht git ≥ 2.26; ältere Versionen lassen Status und Diffs mit `GIT_FAILED` scheitern
  (fail closed). Filter in Submodulen werden nicht abgeschaltet (Status der Submodule liest deren eigene Konfiguration).
- SR3: nur Setup/Teardown; interaktive Konsolen bleiben unverändert (dort erwarten Nutzer das gewohnte Verhalten von cmd).
- CR4 bei unbekannter Zahl: „Trotzdem löschen“ (`force`) löscht den Worktree, den Branch aber nur, wenn git ihn als
  gemergt ansieht (`branch -d`).
