## E2E

Fünf neue Specs `e2e/ausbau1-*.spec.ts` gegen den Server-Build mit FakeBackend. Git läuft dabei echt: Die Test-Repos
liegen im Temp-Ordner des Test-Servers (`E2eServer.makeProject`, verschwindet mit ihm), nie im Checkout oder in einem
Nutzerordner. Jede Datei hat einen eigenen Server (`ownServer`). Kein Live-`claude`, keine festen Wartezeiten.

### Hilfen
- `e2e/support/git.ts` (neu):
  - `findGit` holt den absoluten Pfad von `git` (`resolveExecutable`, kein nackter Name; ohne git überspringt sich der
    Test).
  - `testGit` ist das git des Tests: Argument-Array über `runFile`, ohne geerbte `GIT_*`, eine leere globale
    Konfiguration, `GIT_CONFIG_NOSYSTEM` und ein fester Autor `*.example`.
  - `initRepo` setzt in jedem Repo lokale Einstellungen: Autor, `commit.gpgsign=false`, ein leerer Hooks-Ordner
    (`core.hooksPath`), `core.autocrlf=false`. Der Server ruft git mit seiner eigenen Umgebung auf, also mit der globalen
    Konfiguration des Rechners; die lokalen Werte gewinnen, damit Signatur oder Hooks des Entwicklers nie greifen.
  - `addBareRemote` legt ein Bare-Repo als `origin` an, `main` mit Upstream.
  - `serverSummaries` liest die Session-Liste eines frischen Node-Clients (`cwd`, `worktree`).
- `e2e/support/dom.ts`: neues Feld `__e2eRevealed` für den Rekorder der Suche.

**Änderungen** (Repo mit Bare-Remote, Fenster 1600 px):
- Der Test ändert `README.md` und legt `notes.txt` an, beides nach dem Start der Session.
- Standardfilter „Nur Dateien dieser Session“: leer, die Fake-Session hat nichts geschrieben. Ohne Filter erscheinen
  beide Dateien (`modified`, `added`) mit Diff, alten und neuen Zeilen und Zeilennummern.
- Kommentare:
  - „+“ an einer Zeile, Enter speichert, die Notiz zeigt `README.md:4`.
  - Per Tastatur: Region fokussieren, Pfeil runter, `C`.
- „An Claude senden (2)“: ein Paste-Chip im Composer, die Kommentare sind „Gesendet“, der Knopf ist gesperrt. Der
  nächste Prompt schickt den Chip mit („Fake: received 1 paste(s)“).
- Commit „alle 2 Dateien“:
  - Meldung `Committed <sha>.`, danach „Nothing to commit“.
  - Bereich „Uncommitted“ leer, der Bereich „Session“ zeigt die Dateien weiter.
  - „1 commit ahead“ im Kopf und als Zahl am Push-Knopf.
  - git bestätigt: sauberer Status, Commit-Nachricht stimmt.
- Push: „Pushed.“, keine ahead-Zahl mehr, Push gesperrt, das Bare-Repo hat den Commit.
- **Ohne Remote** (`git remote remove origin`, „Aktualisieren“):
  - Die UI zeigt „No upstream“, Push bleibt aktiv (er würde den Upstream setzen).
  - Der Klick zeigt den Fehler sauber im Panel: `Alert role="alert"`, `data-code="GIT_PUSH_FAILED"`, „Push failed“,
    „Git reported an error.“ und „Git: no remote“.

**Worktree:**
- Neue Session für das Repo: Der Schalter erscheint nach der Repo-Prüfung, der Branch ist mit `parallax/<6>`
  vorbelegt und wird ersetzt durch `e2e/wt-one`, der Hinweis nennt `e2e-wt-one`.
- Die Session läuft in `<repo>/.claude/worktrees/e2e-wt-one`:
  - Ordner da, `git worktree list` und der Branch bestätigen es.
  - `cwd` und `worktree` des Servers stimmen.
  - Die erste Nachricht läuft dort.
- Seitenleiste: Branch mit Worktree-Symbol (`data-worktree`). Gruppiert nach Projekt steht sie in **einer** Gruppe
  des Repos zusammen mit einer normalen Session dort.
- Archivieren:
  - Der Aufräum-Dialog zeigt „No uncommitted changes“, „No commits that exist only here“, „merged into main“ und drei
    Optionen.
  - „Worktree und Branch löschen“ (keine Bestätigung nötig): Ordner und Branch weg, die Session ist archiviert; ihr
    `worktree` bleibt mit `removedAt` stehen (Fix-Runde CR5).
- Projekt-Einstellungen: Setup-Befehl `echo setup-ok` über Einstellungen → Projekte (gespeichert beim Verlassen,
  Badge, `settings.projects`). Die nächste Worktree-Session:
  - kein Banner mehr;
  - Terminal-Tab „Setup“ mit der Ausgabe;
  - die Session startet danach normal.

**Suche:**
- Ein Turn mit einem eindeutigen Wort, danach ist eine andere Session offen.
- Strg+Umschalt+F, Esc schließt ohne Wahl und gibt den Fokus zurück.
- Die Suche findet vier Treffer in einer Gruppe: Titel, Turn-Fazit, Antwort, Prompt. Die Antwort steht vor dem Prompt
  (neueste zuerst), das Wort ist markiert.
- Die Pfeiltasten wählen die Antwort, Enter:
  - öffnet die Session;
  - setzt den Fokus ins Eingabefeld;
  - markiert die Zeile kurz (`data-revealed`, ein `MutationObserver` merkt sie, weil die Markierung nur 2 s steht).

**Übersicht:**
- Textfilter (Ordner): Nur eine Zeile bleibt. Ohne Treffer kommt der Hinweis mit „Filter zurücksetzen“.
- Als ungelesen markieren: die gezeigte Session (Kopfzeilen-Menü) und eine andere (Zeilenmenü). Filter „Ungelesen“
  (Zähler 2) zeigt beide; die gezeigte bleibt ungelesen.
- „Mark as read“ nimmt eine heraus.
- Weg- und zurückwechseln liest die gezeigte. Der Test wartet auf den gesendeten Präsenz-Frame, siehe Stolpersteine.
- Stummschalten am Projektkopf (gruppiert):
  - Glocke-aus im Kopf, `notifications.mutedProjects` gespeichert.
  - Eine Frage (`fake:question` per Node-Client) im stummen Projekt bringt keinen In-App-Hinweis. Die Frage danach im
    anderen Projekt bringt ihn (Positivkontrolle in fester Reihenfolge).
  - Wieder einschalten.

**Elicitation:**

### Einschränkung: URL-Elicitation
Die URL-Anfrage des FakeBackends bleibt höchstens 3 s offen (`FAKE_ELICIT_COMPLETE_MS`, gekappt durch `maxDelayMs`; die
Geschwindigkeit ist im E2E-Server nicht einstellbar). Der Klick auf „Abbrechen“ läuft deshalb gegen den Fake-Server:
Verliert der Test das Rennen (Karte schon zu), startet er eine neue Anfrage, höchstens drei. Was die URL-Karte zeigt,
prüft ein Seitenrekorder statt einer Assertion mit Wiederholpausen.

### Nicht abgedeckt und warum
- „Im Browser öffnen“ der URL-Karte und „Datei öffnen“ im Tab „Änderungen“: gleicher Link- bzw. Datei-Weg wie
  bestehende Specs (`wp64`, `phase3-files`), hier nicht wiederholt.
- Push mit Anmeldefehler („Im Terminal pushen“, `reason: 'auth'`): Ohne echten Remote mit Anmeldung nicht
  auslösbar; Unit-Tests in `features/changes` und `server/git`.
- Branch-Menü (anlegen und wechseln), Bereich „Vorgemerkt“, veraltete Kommentare nach Diff-Änderung,
  Mehrfenster-Synchronisierung der Kommentare: Unit-Tests von WP-111/113.
- Fehlschlagendes Setup („Trotzdem starten“, „Ausgabe ansehen“), Teardown, Portblock (`PARALLAX_WORKTREE_PORT`),
  `.worktreeinclude`, „vorhandenen Worktree wählen“, Aufräumen mit offener Arbeit (Bestätigung, `WORKTREE_DIRTY`):
  Integrationstests von WP-111 und Komponententests von WP-114.
- Suche über andere Rechner, „In Inhalten suchen“ aus Strg+K, Treffer außerhalb des geladenen Fensters (Ausschnitt-Karte
  über `transcript.loadAround`): Unit-Tests von WP-112/115.
- Stumm: Web Notification und Ton bei Fenster im Hintergrund – geprüft ist der In-App-Hinweis; die Zustellung entscheidet
  der Notifier für alle Kanäle gleich (`filter: 'muted'`, Unit-Tests in `notifier.test.ts`).
- Elicitation mit echtem MCP-Server: Live-Abnahme (WP-112 §4), nicht im E2E.

### Stolpersteine
- **Präsenz ist entprellt (250 ms):** Ein Test, der schneller weg- und zurückwechselt, meldet dem Server nie, dass das
  Fenster die Session verlassen hat – die Markierung „ungelesen“ bleibt dann stehen. Für den Server ist das korrekt
  (er sah keinen Wechsel); der Test wartet auf den gesendeten `presence`-Frame mit der neuen `viewingEntryId`.
  Ein Nutzer, der mit Alt+Ziffer in unter 250 ms weg- und zurückspringt, sähe dasselbe.
- Die Suche liefert für einen frischen Turn auch Titel (`Fake: <erste Wörter>`) und Turn-Fazit. Der Test wartet auf den
  automatischen Titel in der Zeile und wählt die Antwort ausdrücklich; ein Titel-Treffer öffnet nur die Session.
- WS-Frames nimmt `page.on('websocket')` nur von Sockets auf, die nach dem Anmelden des Hörers öffnen: Specs mit
  Frame-Rekorder öffnen die App selbst (`new ParallaxApp(page, server).open()`) statt über die Fixture `app`.

### Entscheidung CR5 (Contract-Ergänzung, additiv)

`WorktreeRef.removedAt` (`isoDateTimeSchema.nullable().default(null)`, ältere Dateien und Hosts lesen `null`) und der
Helfer `liveWorktree(ref)` in `src/shared/model.ts`. `worktree.remove` behält den Datensatz und setzt `removedAt`, statt
`worktree: null` zu schreiben. Damit bleibt die Session in der Gruppe ihres Repos (`sessionProjectPath`, Projekt im
Notifier, bekannte Projektwurzeln), obwohl `cwd` auf den gelöschten Ordner zeigt. Alles, was den Worktree selbst braucht,
nimmt `liveWorktree`: Port-Block und `PARALLAX_WORKTREE_PORT`, gemeinsamer Ordner im Modus „existing“, `worktree.inspect`
und `worktree.remove` (danach `VALIDATION_FAILED`), Diff-Basis der git-Befehle, Aufräum-Dialog (`wantsCleanup`,
Archivieren/Entfernen im Session-Menü), Branch-Zeile und Worktree-Hinweis in der Sidebar, Filter „nur Session-Dateien“
im Tab Änderungen.

### Abweichungen und Hinweise

- CR10: `git worktree add` läuft jetzt synchron in `session.create`. Das Zeitlimit des Clients für Befehle (60 s) ist
  kürzer als das von git (120 s); bei sehr großen Repos kann der Client vor dem Server aufgeben. Der Eintrag entsteht
  dann trotzdem und erscheint per Op.
- CR6: PowerShell und fish prüfen je Zeile, eine Zeile muss also eine vollständige Anweisung sein (mehrzeilige Blöcke
  dort nicht unterstützt). Eine Login-Shell der csh-Familie bekommt kein `set -e`.
- SR1: `git config --show-scope` braucht git ≥ 2.26; ältere Versionen lassen Status und Diffs mit `GIT_FAILED` scheitern
  (fail closed). Filter in Submodulen werden nicht abgeschaltet (Status der Submodule liest deren eigene Konfiguration).
- SR3: nur Setup/Teardown; interaktive Konsolen bleiben unverändert (dort erwarten Nutzer das gewohnte Verhalten von cmd).
- CR4 bei unbekannter Zahl: „Trotzdem löschen“ (`force`) löscht den Worktree, den Branch aber nur, wenn git ihn als
  gemergt ansieht (`branch -d`).

### Offene Punkte (nicht blockierend)
- Push ohne jedes Remote bleibt aktiv und scheitert sauber mit `GIT_PUSH_FAILED` („no remote“). Eine Sperre bräuchte
  ein Feld im eingefrorenen `gitStatusSchema` (z. B. Zahl der Remotes).
- Präsenz ist entprellt (250 ms): Wer schneller weg- und zurückwechselt, behält die Markierung „ungelesen“.
- Projekte eines anderen Rechners in Einstellungen → Projekte (`hostId` an `ProjectsSection`), optional ein Befehl
  `git.branches`, ein gehaltener Start-Prompt geht bei einem Server-Neustart während des Setups verloren,
  einstellbare Geschwindigkeit des Fakes für die URL-Elicitation im E2E.
- Live-Probe der Elicitation mit einem echten MCP-Server (optional, nur mit Freigabe des Nutzers).
