# WP-14 – Web-Shell und State

Welle 1a, Worktree `wp/14`. Abhängig von WP-02 (Contracts) und den R0-Fixes. In Welle 1b bauen
WP-15 (Transkript) und WP-16 (Entscheidungen + Composer) auf diesen Bausteinen auf und dürfen

## 1. Auftrag (Kurzfassung)

- **State** (`src/web/state/*`, Namen nach WP-02 §10.3): `Transport` + `createWebSocketTransport` +
  `createMemoryTransport`; `ConnectionManager` für n Hosts (Phase 1 `local`, `sessionKey` nur im
  Client); Handshake (`hello`: neue `serverInstanceId` → Full-Resync, neue `buildId` → Reload),
  Reconnect mit Backoff, ref-gezählte Abos mit `sinceSeq`, Ops über `@shared/sync`, Deltas pro
  Animation-Frame, Befehle mit `cmdId` → Promise auf `ack`, Präsenz; Stores mit Selektoren pro
  Session; Hooks laut §10.3; Client-Seite des Auth-Bootstraps (`#code=` → `POST /api/auth` →
  `history.replaceState`, Status vor dem WS).
- **i18n** (`src/web/i18n/*`): `en` (Default) + `de: typeof en`, Feature-Namespaces laut R0, `t()`
  mit Interpolation + Plural, `tError` für alle Codes (per Test erzwungen), `useT()`, `Intl`-
  Formatierer; Sprache aus den Settings, Start immer Englisch.
- **Theme** Dark (Default) / Light / System über die Design-Tokens.
- **UI-Primitives** (`src/web/ui/*`, shadcn-Stil auf `radix-ui`, nur Tokens, barrierearm).
- **Shell** (`src/web/shell/*`): Sidebar links + eine Session rechts (pane-fähig), Phase-1-Liste,
  Kopfzeile, Empty State, Verbindungs-/Fehler-Banner, Setup-Hinweis, `FeatureSlots`, Fenstertitel
  „(n) Parallax“, zentrale Shortcut-Registry (keine Strg+Alt-Kürzel, Esc vorbereitet).
- **Playground** (`src/web/playground/*`) über `createMemoryTransport` mit `@shared/samples`.
- Tests im Vitest-Projekt `web`; Abnahme `pnpm check`, `pnpm build` (ohne externe URLs), Diff nur
  in Besitz-Pfaden.

### 2.1 Architektur in einem Bild

```
main.tsx ── applyInitialTheme · installShortcutListener · bootApp()
              │ consumeAuthCode (#code= raus) → startSelectionSync (#session=) → startPresenceTracking
              └ createHostConnection('local', WS-Transport, checkAuth = createAuthBootstrap)
                    │ checkAuth → WS → hello/clientHello → host.state, summaries.snapshot
                    │ subscribe{entryId, sinceSeq?} (ref-gezählt) → snapshot | ops | unavailable
                    │ session.ops → Queue → 1×/Frame applySeqOps (@shared/sync) → clientStore
                    └ cmd{cmdId} → ack → Promise (parseCommandResult)
App.tsx ── FeatureSlotsProvider(APP_SLOTS) → ShellEffects (Theme, Sprache, Titel) → AppShell
AppShell ── HostGate → Sidebar | ShellBanners + PaneLayout → SessionPane(Header + Slots)
```

### 2.2 State-API (für WP-15/16; alle Importe aus `@web/state/<datei>`)

**Hooks (`hooks.ts`)** – jeder Hook selektiert genau das, was er zurückgibt (B „Selektoren pro
Session“); Hooks mit „abonniert“ halten die Session per ref-gezähltem `subscribe` offen.

| Hook | Rückgabe | Hinweise |
|---|---|---|
| `useSummaries()` | `SummaryEntry[]` (`{ sessionKey, hostId, summary }`) | alle Hosts, unsortiert, inkl. archiviert; stabil (shallow) |
| `useSummary(key)` | `SessionSummary \| null` | Kanal 1 |
| `useDisplayStatus(key)` | `DisplayStatus \| null` | `deriveDisplayStatus` + Uhr: rendert neu, wenn `rateLimitedUntil`/`wakeupAt` ablaufen |
| `useAttentionCount()` | `number` | „Wartet auf dich (n)“, Fenstertitel |
| `useSummarySelector(key, select, fallback)` | `T` | Ableitung aus der Summary, shallow verglichen (z. B. `(s) => s.permissionMode`); rendert nicht bei anderen Summary-Änderungen |
| `useSummariesLoaded(hostId?)` | `boolean` | `summaries.snapshot` da (Skeleton vs. „gelöscht“) |
| `useSessionMeta(key)` | `SessionMeta` (`{ hasView, loading, unavailable, hasEarlier, conversationId }`) | abonniert; **stabil bei Deltas** (R1W-02) – „Früher laden“, Skeleton, Fehlerzustand |
| `useSessionSelector(key, select, fallback)` | `T` | abonniert; eigene Ableitung aus `SessionViewState`, shallow verglichen; `select` rein, teure Ergebnisse je `view.items` per WeakMap cachen |
| `useTopLevelItemIds(key)` | `readonly string[]` | abonniert; **Zeilen der virtualisierten Liste**: Top-Level-Items in `order` (Items mit `parentToolUseId`, deren Tool-Call nicht geladen ist, stehen oben); stabil bei Deltas und neuen Subagent-Items |
| `useChildItemIds(key, toolUseId)` | `readonly string[]` | abonniert; Items unter einer Agent-Karte (Ebene für Ebene); stabil bei Deltas |
| `selectItemTree(view)`, `selectTopLevelItemIds(view)`, `selectSessionMeta(record)`, `selectSessionRecord(state, key)` | reine Selektoren | für eigene `useSessionSelector`-Ableitungen und Tests |
| `useSessionState(key)` | `SessionRecord` (`{ view, loading, unavailable }`) | abonniert; **ändert sich mit jedem Delta** – in Komponenten `useSessionMeta` nutzen |
| `useSessionView(key)` | `SessionViewState \| null` | abonniert; dito (jedes Delta) – nur Werkzeuge/Tests |
| `useSessionDetail(key)` | `SessionDetail \| null` | abonniert; Queue, Modelle, `init` … |
| `useItemIds(key)` | `readonly string[]` | abonniert; **alle** Items inkl. Subagent – für die Liste `useTopLevelItemIds` |
| `useItem(key, itemId)` | `TranscriptItem \| null` | **abonniert nicht**; rendert nur bei Änderung dieses Items (O(1) über Index-Cache) |
| `useDecisions(key)` | `readonly Decision[]` | abonniert; offen + abgelaufen, älteste zuerst |
| `useDecision(key, decisionId)` | `Decision \| null` | abonniert nicht (für `DecisionCard`); offen/abgelaufen, `null` nach `decision.resolved` (Regel architecture §2.3e) |
| `useSessionSubscription(key)` | – | nur das Abo (z. B. für eine Komponente ohne Daten) |
| `useSelectedSession()` | `[key \| null, select]` | spiegelt `#session=hostId:entryId` |
| `useCommand()` / `sendCommand(key \| null, cmd)` | `Promise<CommandResult<cmd.name>>` | `null` = lokaler Host (`session.create`, `settings.update`); wirft `ClientCommandError` |
| `useHostState(hostId?)`, `useHostRecord(hostId?)`, `useConnectionStatus(hostId?)` | Host-Zustand, Verbindungs-Record, `'connecting' \| 'open' \| 'reconnecting' \| 'closed'` | `HostRecord.upgradeRejected`: angemeldet, aber WS wiederholt vor `hello` geschlossen |
| `useSessionConnectionStatus(key)` | `ConnectionStatus` | Host der Session (z. B. „Senden“ nur bei `open`) |
| `useWindowPresence()` | `{ focused, visible, typing }` | Präsenz dieses Fensters |
| `dismissNotification(id)` | In-App-Benachrichtigungen (`notify`) | Zustellung über `notifications/delivery.ts`; `useNotifications()` entfiel in den R3-Fixes (ohne Nutzer, R3-11) |
| `useHostCounter(counter, hostId?)` | `number` | Zähler der Verbindung (`invalidMessages` …, R3-05) |

**Befehle und Fehler:** `sendCommand(sessionKey, { name: 'decision.respond', entryId, decisionId,
response })` → `{ outcome }`. Abgelehnt wird immer mit `ClientCommandError` (`error: ErrorPayload`,
`code`); anzeigen mit `tError(error.error)` bzw. `errorPayloadOf(caught)` (`connection.ts`). Lokale
Codes: `VALIDATION_FAILED` (Befehl verletzt das Schema, wird nicht gesendet), `CONNECTION_LOST`
(neue Server-Instanz, Verbindung geschlossen), `COMMAND_TIMEOUT` (60 s), `INVALID_MESSAGE`
(`ack.result` passt nicht). Unbestätigte Befehle werden nach einem Reconnect zur selben Instanz mit
**derselben** `cmdId` erneut gesendet.

**Weitere Bausteine:**
- `actions.ts`: `loadEarlier(key, { limit? })` – `transcript.loadEarlier` vor dem ältesten Item,
  Merge mit `mergeItems` in den Store; parallele Aufrufe teilen sich eine Anfrage (WP-15).
- `presence.ts`: `reportTyping()` – vom Composer bei Eingabe aufrufen (Präsenz `typing`, 5 s).
- `notices.ts` (R1W-07): lokale Hinweise des Fensters – `showNotice(content, { tone?, sessionKey?,
  durationMs?, id? }) → id` mit `content = { text: TranslationKey, params? } | { error:
  ErrorPayload }`, Kurzformen `showTextNotice(key, params?, options?)` und
  `showErrorNotice(error, options?)`, `dismissNotice(id)`, `useNotices()`. Ton-Default `error` für
  Fehler, sonst `info`; Dauer 6 s (Fehler 10 s), `durationMs: null` = bis zum Schließen; gleiche
  `id` ersetzt (kein Stapeln); max. 5. Anzeige im `NotificationCenter` (unten rechts, Fehler
  `role="alert"`, „Session anzeigen“ bei `sessionKey`), Übersetzung beim Rendern. Beispiel WP-16:
  `catch (e) { showErrorNotice(errorPayloadOf(e), { sessionKey }) }`.
- `clock.ts`: `useNow(intervalMs)`, `useNowUntil(deadlines)` (rendert nur, wenn eine Deadline
  vergeht – nicht bei Ticks anderer Uhr-Nutzer) – für relative Zeiten/Countdowns; nie
  `Date.now()` im Render (React-Compiler-Lint `purity`).
- `settings.ts`: `useSettings()`, `updateSettings(patch)` (optimistisch, bei Fehler zurückgesetzt).
- `theme.ts`: `useResolvedTheme()` (`'dark' | 'light'`, z. B. Shiki-Theme), `useThemeController(theme)`,
  `resolveTheme`, `applyResolvedTheme`, `applyInitialTheme`.
- `connection.ts`: `createHostConnection(options)` (`ManagedHostConnection`: `start`, `stop`,
  `retryNow`, `flush`), `registerConnection`, `getConnection(hostId?)` (unbekannter Host → neutraler
  Stand-in, wirft nie), `retryConnection`, `unregisterConnection`, `ClientCommandError`.
- `transport.ts`: `Transport`, `createWebSocketTransport(url, socketFactory?)`,
  `createMemoryTransport()` (Obermenge von §10.3: `serverSend`, `serverSendRaw`, `serverClose(code)`,
  `sent`, `sentOfType(type)`, `clearSent`, `connected`, `connectCount`, `onClientMessage`, `onConnect`).
- `fake-host.ts`: `FakeHost` – In-Memory-Server hinter dem MemoryTransport (Handshake, Seq,
  Ringpuffer, Snapshot/Replay, Standard-Antworten auf alle Befehle; `pushOps`, `upsertSummary`,
  `patchSummary`, `streamAssistantText`, `interruptStreams`, `restart({ newInstance })`,
  `commands`, `subscribed`). Standardverhalten seit R1W-22: `decision.respond` löst auf **und**
  schreibt das Outcome per `item.upsert` in den auslösenden `tool_call` (`decision.outcome`,
  Status `running`/`done`/`denied`); `session.interrupt` bricht laufende Streams ab (Text bis dahin,
  `aborted: true`); `transcript.loadEarlier` liefert ältere Items aus der Server-Sicht (Snapshots
  sind auf `LIMITS.snapshotItems` gekappt). Keine Queue-Simulation – dafür `onCommand`. Für
  Komponententests von WP-15/16: `startScenario('overview')` (Playground) oder `FakeHost` direkt.
- `lib/storage.ts`: `storageKey(namespace, …parts)` → `parallax.<namespace>.<…>` für Feature-Schlüssel
  (WP-16: `storageKey('composer', 'draft', sessionKey)`), `readStorage`/`writeStorage`,
  `storageAvailable(kind)`.

**Verbindungsverhalten (normativ umgesetzt, `docs/architecture.md` §5/§5.1, WP-02 §7.1):**
Auth-Status vor **jedem** WS-Versuch (nicht angemeldet → kein WS, Ansicht „Nicht angemeldet“;
nicht erreichbar → Backoff 0,5 s · 2^n bis 15 s, ±20 %); Close 4401 → „Nicht angemeldet“, 4503 →
„Server beendet“, 4409 → wie Versionskonflikt, alles andere → Reconnect. Neue `serverInstanceId`
(im `hello` oder schon im Auth-Status) → Summaries, Views, Seqs verwerfen, offene Befehle →
`CONNECTION_LOST`, Abos ohne `sinceSeq`. Andere `protocolVersion`/`buildId` → `location.reload()`
höchstens 1× je 30 s (sessionStorage; ohne nutzbaren sessionStorage nie automatisch, R1W-12), sonst
Banner `PROTOCOL_VERSION_MISMATCH`. Kein `hello` binnen 10 s → Socket schließen, Backoff (R1W-11).
Dreimal in Folge angemeldet, aber Socket vor `hello` zu → `HostRecord.upgradeRejected` mit eigenem
Hinweis (V1-15). Snapshots/`session.unavailable` ohne Abo werden verworfen (R1W-18). Lücke in Live-Ops →
einmal `subscribe{sinceSeq: lastSeq}`. Abmelden eines Abos verzögert (1,5 s, StrictMode/schnelles
Umschalten); Views abgemeldeter Sessions bleiben im LRU-Cache (8) für ein schnelles Replay.
Präsenz nach jeder Änderung (entprellt 250 ms), auch im `clientHello`.

### 2.7 Abweichungen und Entscheidungen

1. **`send`/`useCommand` generisch über das Befehlsobjekt** (`send<C extends Command>(cmd: C):
   Promise<CommandResult<C['name']>>`) statt `<N extends CommandName>(cmd: Extract<…>)`: TypeScript 6
   kann die Extract-Signatur nicht mit der Implementierung abgleichen (TS2719). Aufrufe sind
   identisch, das Ergebnis bleibt typisiert.
2. **`createMemoryTransport()`** liefert eine Obermenge (u. a. `serverClose`, `onConnect`) und
   **`PlaygroundModule.slots`** ist eine optionale Erweiterung von architecture §2.3c.
3. **Zusätzliche State-Bausteine** (`actions.ts` `loadEarlier`, `fake-host.ts`, `clock.ts`,
   `useItemIds`, `useDecision`, `useSessionState`), weil Features den Store nicht schreiben dürfen.
4. **Neue-Session-Formular** (Ordner + Start) im Empty State als Phase-1-Minimum; der Dialog mit
   Ordner-Browser/Profilen folgt in Phase 2.
5. **Design:** ruhige Grautöne nahe VS Code, ein warmer Akzent (`--brand`, Claude-Orange) für
   Primär-Buttons/Fokus; Text 13 px (`text-ui`), 11 px (`text-2xs`); Profilfarben
   `--profile-<color>`; dünne Scrollbars. Theme-Cache in localStorage gegen Hell-Flackern.
6. **Benachrichtigungen:** `in_app` als Hinweis unten rechts, `system` als Web Notification nur
   bei erteilter Berechtigung (sonst in-app); die Berechtigungsanfrage per Klick folgt (Phase 2).

### 2.11 R2-Fixes Web (Branch `fix/r2-web`, 15.10.2026)

Wünsche aus WP-15/16, bewertet in `docs/wp/R2-web.md` (ADR-043, ADR-044):
- **Modus-Labels (R2W-03):** `shell.permissionMode.*` ist die einzige Bezeichnung der Modi (en
  „Manual“, „Accept edits“, „Plan“, „Auto“; de „Manuell“, „Edits automatisch“, „Plan“, „Auto“) –
  Kopfzeile, ModePicker, Umsetzen-Knopf und Transkript nutzen sie. Die Kopfzeile bleibt ein nicht
  bedienbarer Status (Modell, Modus, Badge „n eingereiht“ = einzige Queue-Anzeige neben dem
  Transkript, ADR-041/042); `SessionHeader.tsx` unverändert.
- **Shortcut-Hilfe (R2W-11):** Einträge mit `allowInInputs` tragen „auch in Textfeldern“
