# WP-80 – Web für mehrere Rechner

Teilpaket des Features „Mehrere Rechner“ (Plan `docs/wp/WP-75.md` §4.4 normativ, Spezifikation `docs/wp/WP-76.md`
§C/§D). Branch `wp/80` von `feature/multi-host`, parallel zum Server-Teil WP-79. Gearbeitet nur gegen die Contracts v5
und den Fake-Host; die E2E-Prüfung macht der Koordinator.

## 1. Auftrag (Kurzfassung)

1. Verbindungen je Rechner (`src/web/state/**`) mit den Close-Codes 4502/4410/4403.
2. Seitenleiste „Gruppieren nach“ (Rechner, Verzeichnis), einklappbar, Badge des Rechners – nur mit eingebundenen
   Rechnern.
3. „Neue Session“ mit Wahl des Rechners.
4. Host-abhängige URLs (Dateien, Plan, Blobs, Uploads).
5. Einschränkungen für freigegebene Sessions (Editor, Explorer, „Öffnen mit“ aus; Anzeige-Einstellungen vom eigenen
   Rechner).
6. Einstellungen, Teil „Andere steuern“.
7. Symbol in der Kopfzeile.
8. Fake-Host und Playground.
9. i18n-Namensraum `hosts`.
10. Tests in happy-dom.

## 3. Ergebnis

### 3.1 Zustand (`src/web/state`)
- **Phasen:** `HostPhase` um `incompatible` und `revoked` erweitert (beide geschlossen, `status: 'closed'`).
- **`createHostConnection({remote: true})`:** nie Home-Host (kein `buildId`-Vergleich, kein Neuladen). Close 4502 →
  offene Befehle mit `HOST_UNREACHABLE` beenden, Wiederverbinden mit dem normalen Backoff; bis zum nächsten `hello`
  scheitern neue Befehle sofort mit `HOST_UNREACHABLE` (nicht erst nach dem Befehls-Timeout). Close 4410 oder ein
  anderes Protokoll im `hello` → `incompatible` (`HOST_INCOMPATIBLE {protocol, version}` aus dem `hello`), Close 4403 →
  `revoked`; in beiden Fällen kein Neuladen und keine weiteren Versuche, bis `retryNow()` kommt. Die lokale Verbindung
  behandelt diese Codes unverändert als verlorene Verbindung.
- **`remote-hosts.ts`** (neu): `startRemoteHosts` folgt `HostState.remoteHosts` der lokalen Verbindung, legt je Eintrag
  eine Verbindung auf `hostWsPath(hostId)` an (registriert, gestartet) und entfernt verschwundene Rechner zur
  Laufzeit (`forgetHost`: Host-Datensatz, Sessions, Benachrichtigungen, Auswahl). Meldet der Server einen Rechner wieder
  als `connected`, versucht eine wartende, inkompatible oder getrennte Verbindung sofort (`retryNow`) – keine eigene
  Schleife; „Neu verbinden“ (`hosts.reconnect`) wirkt darüber. Verdrahtet in `bootstrap.ts`.
- **`hosts.ts`** (neu): `useRemoteHosts`, `useHasRemoteHosts`, `useRemoteHost`, `useMultiHostRole`, `useRemoteAccess`,
  `selectHostAvailability`/`useHostAvailability` (`available`, `connecting`, `unreachable`, `incompatible`, `revoked`;
  dieser Rechner immer `available`), `hostIdOf`, `sendHostCommand(hostId, cmd)`, `commandHost` (`link.open` immer an
  `local`, ADR-208). `sendCommand` nutzt `commandHost` ebenfalls.
- **Anzeige-Einstellungen:** `useHookDisplay()` und `useTranscriptView()` lesen immer diesen Rechner (WP-75 §4.4); die
  Aufrufer in `features/transcript` (`SystemRow`, `SubagentPanel`) geben keinen Host mehr mit.

### 3.2 Helfer (`src/web/lib`) und Inhalts-URLs
- **`host-urls.ts`:** `hostOfSession`, `sessionBlobUrl`, `sessionFileUrl`, `sessionAttachmentsPath` – nur aus
  `@shared/http` (`hostBlobPath`, `hostFileUrl`, `hostAttachmentsPath`); dieser Rechner behält die lokalen Routen.
- **Umgestellt:** `features/files/state/file-source.ts` (Text und URL), `features/decisions/state/plan-data.ts`
  (Plan-Datei), `features/transcript/state/blob-source.ts` (`blobSource(id, hostId)`), `state/full-text.ts`
  („Vollständig laden“ über den `sessionKey`), `components/ImageThumb.tsx` (Rechner aus dem neuen `BlobHostContext`,
  gesetzt in `TranscriptView` und `SubagentPanel`), `features/composer/lib/upload.ts` (optionales
  `UploadRequest.sessionKey` → `sessionAttachmentsPath`).
- **`host-colors.ts`:** `index.css` hat keine Host-Tokens (Koordinator-Bereich); die acht Host-Farben werden auf die
  acht Profil-Tokens abgebildet (rose → pink, orange → red), jede auf ein anderes. Das Badge trägt immer den Kurznamen
  (`hostShortName`), die Farbe steht nie allein.
- **`session-order.ts`:** `sidebarLayout` (keins = flach, Verzeichnis = Gruppen wie bisher – gleicher Pfad auf zwei
  Rechnern = zwei Gruppen –, Rechner = je Rechner ein Block in fester Reihenfolge, beide = Verzeichnisse im Rechner);
  ein Rechner ohne Sessions behält seinen Block. `visibleSidebarOrder` lässt eingeklappte Gruppen aus,
  `groupKeysOfEntry` nennt die Gruppen einer Ziel-Session (Aufklappen). Schlüssel `host:<id>` und
  `folder:<id>|<pfadschlüssel>`.
