## 1. Auftrag

### Ziel
Die Engine übergibt eine Session an eine externe Konsole und holt sie samt Verlauf zurück, plant
„Fortsetzen nach dem Rate-Limit“, sendet Bild-Anhänge als `image`-Blöcke und macht native Toasts
klickbar (Protokoll-URI) bzw. stumm nach Einstellung. Das FakeBackend bekommt die Szenarien dafür.

### Anforderungen (normativ)
1. **Bild-Anhänge (ADR-103):** `session.create.prompt` und `session.sendPrompt` mit
   `attachments`: je `blobId` → `BlobStore.get`; fehlt → `BLOB_NOT_FOUND{blobId}`; Typ ∉
   `ATTACHMENT_MEDIA_TYPES` → `UNSUPPORTED_MEDIA_TYPE`; `bytes > LIMITS.imageBytes` →
   `PAYLOAD_TOO_LARGE` – alles vor jedem Start/Senden. Gesendet: `OutgoingContent` = Bilder (base64)
   zuerst, dann Text (leerer Text entfällt). `registerPrompt` mit den `BlobRef`s → das
   `user_message`-Item und `detail.queue` tragen die Anhänge. Titel aus dem Text wie bisher.
2. **Externe Konsole (ADR-104, §4.12):**
   - `session.openExternal`: Vorbedingungen; Lifecycle-Lock; `closeRuntime(s, core, 'handoff')`;
     `consoleLaunchFor({profileId, entryId, cwd, resumeSessionId, model: entry.modelSetting,
     permissionMode: erlaubter gespeicherter Modus})`; `consoleLauncher.open(spec)`; Fehler →
     `EXTERNAL_CONSOLE_FAILED{reason}`, Zustand bleibt ruhend; Erfolg → `Entry.external = {pid,
     processStartedAt, since: now, conversationId}`, Status-Event `{type:'external', active:true}`,
     px-Item `system/handoff{phase:'external'}`, Summary `external{running:true}`; Ergebnis `{pid}`.
   - Überwachung: alle `externalPollMs` je Eintrag `consoleLauncher.state(process)`; `ended` →
     Rückkehr (unten); `unknown` → weiter warten.
   - `session.reclaim` bzw. automatische Rückkehr: `running`/`unknown` → `EXTERNAL_STILL_RUNNING{pid}`
     (nur beim Befehl); sonst `readHistory({sessionId, cwd, launch})`, Nachrichten mit `timestamp ≥
     since − 5 s` (ohne Zeitstempel: verwerfen), `normalizeHistory` mit `nextOrder = lastOrder + 1`,
     Items, deren ID im Log schon existiert, verwerfen; Rest an das Log anhängen und veröffentlichen;
     px-Item `system/handoff{phase:'returned', importedItems:n}`; `Entry.external = null`,
     `{type:'external', active:false}` → `sleeping`; KI-Titel abfragen wie nach einem Turn. Ergebnis
     `{importedItems}`. Lese-Fehler → Rückkehr ohne Import (`importedItems: 0`, Log `warn`).
   - Serverstart: Eintrag mit `external` → `state()`; `running`/`unknown` → `external` + Überwachung;
     `ended` → Rückkehr. Shutdown lässt die Konsole in Ruhe.
   - `session.consoleCommand`: `consoleLaunchFor` → `{command: consoleCommandText(spec), sessionId}`;
     ändert nichts (auch archiviert/extern erlaubt).
   - Während `external`: Befehle laut §4.12, kein Schlaf, kein Auto-Retry.
3. **Fortsetzen nach Rate-Limit (ADR-112):** `session.continueAfterLimit{enabled:true}`: `at =
   facts.rateLimitedUntil` (Zukunft) sonst `now`; `Entry.continueAt = at`, Status-Event
   `{type:'wakeup', at}`; Timer; fällig → `wakeup null`, `continueAt null`, Resume falls nötig,
   Prompt `continue` (Konstante `CONTINUE_PROMPT`) mit `priority 'next'`. `enabled:false` → beides
   löschen. Jeder `sendPrompt`/`session.create` mit Prompt löscht einen Plan; Archivieren auch
   (WP-31). Serverstart: `continueAt` in der Zukunft → Timer; ≤ `continueGraceMs` überfällig →
   sofort; älter → verwerfen. Ergebnis `{continueAt}`.
4. **Native Toasts (ADR-109):** `nativeToasts.ts` setzt `launchUri = systemIntegration?.
   toastLaunchUri(entryId) ?? null` und `silent = !settings.notifications.events[kind].sound`
   (Einstellungen zum Zeitpunkt des Toasts).
5. **FakeBackend:** (a) Prompt mit Bildern → Antwort „Fake: received N image(s)“; (b) Szenario-Wort
   `fake:image` → ein Tool-Call (`Read` auf `fake-shot.png`) mit Bild-Ergebnis (kleines gültiges PNG,
   base64, ≤ 1 KB); (c) `simulateConsoleTurn` für den Fake-Verlauf (Zeitstempel = `at`); (d)
   `fake:ratelimit` mit `resetsAt` ≈ 60 s in der Zukunft (für E2E „Fortsetzen um“), bestehendes
   Verhalten sonst unverändert; (e) `createFakeClaudeIntegration({store?: MutableProfileStore})` –
   ein übergebener (persistenter) Store gewinnt über `profiles`, `checkProfile` schreibt den
   ok-Status hinein, `consoleLaunchFor` liefert `{executablePath: FAKE_CLAUDE_PATH, args: ['--resume',
   id], env: {}, explicitEnv: {}, cwd}` (bzw. den gesetzten Launch-Fehler).
