## 1. Auftrag

### Ziel
Die Engine übergibt eine Session an eine externe Konsole und holt sie samt Verlauf zurück, plant
„Fortsetzen nach dem Rate-Limit“, sendet Bild-Anhänge als `image`-Blöcke und macht native Toasts
klickbar (Protokoll-URI) bzw. stumm nach Einstellung. Das FakeBackend bekommt die Szenarien dafür.

### Anforderungen (normativ)
1. **Bild-Anhänge (ADR-103):** `session.create.prompt` und `session.sendPrompt` mit
   `attachments`: je `blobId` → `BlobStore.get`; fehlt → `BLOB_NOT_FOUND{blobId}`; Typ ∉
   `ATTACHMENT_MEDIA_TYPES` → `UNSUPPORTED_MEDIA_TYPE`; `bytes > LIMITS.imageBytes` →
   `PAYLOAD_TOO_LARGE` – alles vor jedem Start/Senden. Gesendet: `OutgoingContent` = Bilder (base64)
   zuerst, dann Text (leerer Text entfällt). `registerPrompt` mit den `BlobRef`s → das
   `user_message`-Item und `detail.queue` tragen die Anhänge. Titel aus dem Text wie bisher.
2. **Externe Konsole (ADR-104, §4.12):**
   - `session.openExternal`: Vorbedingungen; Lifecycle-Lock; `closeRuntime(s, core, 'handoff')`;
     `consoleLaunchFor({profileId, entryId, cwd, resumeSessionId, model: entry.modelSetting,
     permissionMode: erlaubter gespeicherter Modus})`; `consoleLauncher.open(spec)`; Fehler →
     `EXTERNAL_CONSOLE_FAILED{reason}`, Zustand bleibt ruhend; Erfolg → `Entry.external = {pid,
     processStartedAt, since: now, conversationId}`, Status-Event `{type:'external', active:true}`,
     px-Item `system/handoff{phase:'external'}`, Summary `external{running:true}`; Ergebnis `{pid}`.
   - Überwachung: alle `externalPollMs` je Eintrag `consoleLauncher.state(process)`; `ended` →
     Rückkehr (unten); `unknown` → weiter warten.
   - `session.reclaim` bzw. automatische Rückkehr: `running`/`unknown` → `EXTERNAL_STILL_RUNNING{pid}`
     (nur beim Befehl); sonst `readHistory({sessionId, cwd, launch})`, Nachrichten mit `timestamp ≥
     since − 5 s` (ohne Zeitstempel: verwerfen), `normalizeHistory` mit `nextOrder = lastOrder + 1`,
     Items, deren ID im Log schon existiert, verwerfen; Rest an das Log anhängen und veröffentlichen;
     px-Item `system/handoff{phase:'returned', importedItems:n}`; `Entry.external = null`,
     `{type:'external', active:false}` → `sleeping`; KI-Titel abfragen wie nach einem Turn. Ergebnis
     `{importedItems}`. Lese-Fehler → Rückkehr ohne Import (`importedItems: 0`, Log `warn`).
   - Serverstart: Eintrag mit `external` → `state()`; `running`/`unknown` → `external` + Überwachung;
     `ended` → Rückkehr. Shutdown lässt die Konsole in Ruhe.
   - `session.consoleCommand`: `consoleLaunchFor` → `{command: consoleCommandText(spec), sessionId}`;
     ändert nichts (auch archiviert/extern erlaubt).
   - Während `external`: Befehle laut §4.12, kein Schlaf, kein Auto-Retry.
3. **Fortsetzen nach Rate-Limit (ADR-112):** `session.continueAfterLimit{enabled:true}`: `at =
   facts.rateLimitedUntil` (Zukunft) sonst `now`; `Entry.continueAt = at`, Status-Event
   `{type:'wakeup', at}`; Timer; fällig → `wakeup null`, `continueAt null`, Resume falls nötig,
   Prompt `continue` (Konstante `CONTINUE_PROMPT`) mit `priority 'next'`. `enabled:false` → beides
   löschen. Jeder `sendPrompt`/`session.create` mit Prompt löscht einen Plan; Archivieren auch
   (WP-31). Serverstart: `continueAt` in der Zukunft → Timer; ≤ `continueGraceMs` überfällig →
   sofort; älter → verwerfen. Ergebnis `{continueAt}`.
4. **Native Toasts (ADR-109):** `nativeToasts.ts` setzt `launchUri = systemIntegration?.
   toastLaunchUri(entryId) ?? null` und `silent = !settings.notifications.events[kind].sound`
   (Einstellungen zum Zeitpunkt des Toasts).
5. **FakeBackend:** (a) Prompt mit Bildern → Antwort „Fake: received N image(s)“; (b) Szenario-Wort
   `fake:image` → ein Tool-Call (`Read` auf `fake-shot.png`) mit Bild-Ergebnis (kleines gültiges PNG,
   base64, ≤ 1 KB); (c) `simulateConsoleTurn` für den Fake-Verlauf (Zeitstempel = `at`); (d)
   `fake:ratelimit` mit `resetsAt` ≈ 60 s in der Zukunft (für E2E „Fortsetzen um“), bestehendes
   Verhalten sonst unverändert; (e) `createFakeClaudeIntegration({store?: MutableProfileStore})` –
   ein übergebener (persistenter) Store gewinnt über `profiles`, `checkProfile` schreibt den
   ok-Status hinein, `consoleLaunchFor` liefert `{executablePath: FAKE_CLAUDE_PATH, args: ['--resume',
   id], env: {}, explicitEnv: {}, cwd}` (bzw. den gesetzten Launch-Fehler).

### 2.2 Verhalten (Kurzfassung)

- **Anhänge:** `session.create` prüft vor dem Anlegen (Fehler → kein Eintrag, kein Start).
  `sendPrompt` prüft **im Lifecycle-Lock** vor Start/Senden; reine Textprompts setzen Titel,
  Retry-/Plan-Löschung wie bisher sofort, mit Anhängen erst nach erfolgreicher Prüfung.
- **Konsole öffnen:** im Lock: `SESSION_NOT_STARTED` → `SESSION_BUSY` → ohne Launcher
  `EXTERNAL_CONSOLE_FAILED {reason:'unavailable'}` (nichts geschlossen) → Plan löschen →
  `closeRuntime('handoff')` → Waisen-Prüfung abwarten → abgelaufene Karten schließen →
  `consoleLaunchFor` (Profilfehler unverändert) → `open` (Fehler → `EXTERNAL_CONSOLE_FAILED {reason}`,
  bereinigt) → `Entry.external`, `external{active:true}`, `handoff/external`, Überwachung.
- **Rückkehr:** Prüfung alle `externalPollMs`; `ended` → `external.running:false` in der Summary,
  `launchSpecFor` + `readHistory`, Nachrichten mit Zeitstempel ≥ `since − 5 s`, `normalizeHistory`
  ab `lastOrder + 1`, IDs aus dem ganzen Log der Unterhaltung verworfen, Rest per `emit` (Log, Mirror,
  `lastOrder`), `handoff/returned {importedItems}`, `external = null`, `sleeping`, KI-Titel und
  Git-Branch. Lese-/Launch-Fehler → `importedItems: 0` + `warn`. `session.reclaim` ohne Handoff →
  `{importedItems: 0}` (die automatische Rückkehr kann gewonnen haben).
- **Serverstart:** `continueAt` künftig → `wakeup` + Timer, ≤ 1 h überfällig → sofort, älter →
  gelöscht (`info`-Log); `external` → `state()` im Hintergrund (`externalChecksDone()`).
  `runState external` ohne Handoff-Datensatz → `sleeping` (`warn`). Shutdown: nur Timer weg.
- **Fortsetzen:** fällig → `wakeup null`, `continueAt null`, archiviert/extern → nichts, sonst im Lock
  Resume falls nötig + `continue` (`next`); Startfehler zeigt der Status (`failStart`).
- **Toasts:** `toastShowOptions` mit den Einstellungen zum Zeitpunkt des Toasts.

### 2.3 Entscheidungen

1. **`onProfileChanged(profileId?: ProfileId | null): void`** (ADR-102): `PersistentProfileStore.onChange`
   liefert keine ID und feuert auch bei `setClaudeStatus` (Profiltest, Start-Check des
   Default-Profils). Daher vergleicht die Engine je Profil `profileCacheKey` (SHA-256 über
   `executable`, `env`, `configDir`, `args`, `passRawArgs`) mit dem zuletzt gesehenen Stand; nur bei
   Änderung bzw. Löschung werden Modell-Katalog inkl. Auflösung (Speicher + `model-catalogs.json`)
   und `lastEnv` ruhender Einträge verworfen, offene Sichten ruhender Einträge bekommen die
   Alias-Liste; ein gelöschtes Profil verliert auch seine Abo-Limits. Umbenennen/Farbe/Default/Status
   behalten die Caches (wie der Auflösungs-Cache von WP-32). `HostState` wird immer neu veröffentlicht.
2. **`openExternal` löscht einen Fortsetzen-Plan** und schließt abgelaufene Karten (die Konsole setzt
   die Unterhaltung fort; ein später feuernder Plan wäre ein zweiter Schreiber). Ohne
   `ConsoleLauncher` bleibt ein Handoff eines früheren Laufs `external` (Zustand `unknown`, ADR-051;
   `reclaim` → `EXTERNAL_STILL_RUNNING`).
3. **Secrets:** Die Konsolen-Spec wird nie geloggt; ein Launcher-Fehlertext wird vor Log und
   `EXTERNAL_CONSOLE_FAILED {reason}` von allen `explicitEnv`-Werten und Secret-Env-Werten
   (`isSecretEnvKey`, ≥ 4 Zeichen, längste zuerst) sowie per `redactText` bereinigt und gekappt.
   Nur das Ergebnis von `session.consoleCommand` enthält die Werte (gewollt, ADR-104).

Weitere: `continueAfterLimit(true)` ohne Claude-Session hat laut Tabelle keinen Fehler (sendet dann
`continue` als ersten Prompt); `continueAfterLimit(false)` ist idempotent. Der native Toast bekommt
`launchUri`/`silent` als viertes, optionales Argument von `NativeToasts.show` (berechnet in
`nativeToasts.ts`), damit `createNativeToasts` in `compose.ts` unverändert bleibt.

### 2.4 Verdrahtung für WP-40 (`app/compose.ts`)

```ts
const fakeBackend = createFakeBackend({ speed });                       // Fake-Server
const consoleLauncher = config.backend === 'fake'
  ? createFakeConsoleLauncher({ runMs: 1500, onRun: (spec) => {
      const id = spec.args[spec.args.indexOf('--resume') + 1];
      if (id !== undefined) fakeBackend.simulateConsoleTurn(id, new Date());
    } })
  : createConsoleLauncher();
const claude = config.backend === 'fake'
  ? createFakeClaudeIntegration({ store: profileStore })                // persistenter Store gewinnt
  : createClaudeIntegration({ appVersion, profiles: profileStore });
createSessionManager({ …, consoleLauncher, systemIntegration: system,   // system = createSystemIntegration(…)
  options: { /* optional E2E: externalPollMs: 500 */ } });
profileStore.onChange(() => manager.onProfileChanged());                // ohne ID: alle Profile prüfen
```
Defaults: `externalPollMs` 5000, `continueGraceMs` 3 600 000. `manager.onProfileChanged()` ruft
`publishHostState()` selbst – ein zusätzlicher Aufruf ist unnötig.
