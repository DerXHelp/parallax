# WP-106 – Desktop-Integration unter Linux (Linux-Plan WP-100, Welle L2)

Branch `wp/106` von `feature/linux` (nach L1 und 102e), Worktree `.worktrees/wp-106`. Grundlage: `docs/wp/WP-100.md`
§5.3 (Chrome), §5.5–5.8, `docs/wp/WP-101.md` (Chrome im Container, `notify-send` 0.8 mit `--action --wait`),
`docs/wp/WP-102.md` (Fähigkeiten, Editor-Regeln, 102e). Besitz-Pfade: CLAUDE.md „Linux“, **L2, WP-106**.

## Umfang
1. **Chrome** (`lib/chrome.ts`, `launcher/chromeWindow.ts`): Suche unter Linux – Einstellung → `google-chrome-stable`,
   `google-chrome`, `chromium`, `chromium-browser` auf `PATH` → `/snap/bin/chromium`; App-Fenster mit eigenem Profil
   (Snap-Chromium: Profil nicht in versteckten `$HOME`-Ordnern), `--class`/`StartupWMClass` passend zur
   `.desktop`-Datei. Versions-Ermittlung ohne PE (`--version`).
2. **Benachrichtigungen** (`lib/toast.ts`, `sessions/nativeToasts.ts`): `notify-send --app-name=Parallax
   --replace-id … --action=open=… --wait --print-id`; Klick öffnet die Session wie der Windows-Toast; Rückfall
   D-Bus über `gdbus`; im Server-Modus aus.
3. **Systemintegration** (`system/**`): `.desktop`-Programmeintrag (`~/.local/share/applications/parallax.desktop`,
   Icon PNG/SVG), XDG-Autostart (`~/.config/autostart/parallax.desktop`), `parallax:` über
   `MimeType=x-scheme-handler/parallax` + `xdg-mime default`; eigene Einträge erkennen, fremde nie überschreiben
   (wie unter Windows). Nur auf dem produktiven Server (`available`), nie in Tests (Wächter wie `system/guard.ts`).
4. **Konsole** (`system/console.ts` Linux-Variante): Terminal-Emulator aus `console.terminalEmulator` (102e) →
   `xdg-terminal-exec` → `x-terminal-emulator` → bekannte (Ptyxis, GNOME Terminal, Konsole, Xfce Terminal, kitty,
   Alacritty, WezTerm, foot, xterm) mit je eigener Syntax für Arbeitsordner und Befehl; PID über `/proc` (Prozess mit
   `PARALLAX_ENTRY_ID`). Dient dem Shell-Fenster (WP-105) und der externen Konsole.
5. **Externe Konsole** (`sessions/external.ts`, `claude/consoleCommand.ts`): unter Linux `claude --resume …` im
   Terminal-Emulator; Konsolenbefehl mit POSIX-Quoting (`PARALLAX=1 PARALLAX_ENTRY_ID=… claude --resume …`) je
   Plattform des Hosts. Fix für alle Plattformen: ohne nutzbaren Starter ist der Launcher `null` (vor dem Schließen
   der SDK-Abfrage, `external.ts:135`). **„In Terminal fortsetzen“** hat der Koordinator in 102e schon umgesetzt
   (`openInTerminal`/`handOff` in `external.ts`, `TerminalService.openClaude`) – nicht umbauen, nur mitziehen.
6. **Editor und Dateien** (`files/editors.ts`, `files/open.ts`, `host/linkCommands.ts`): Editor-Vorgaben Linux
   (102e: VS Code, VSCodium, Zed, Sublime Text, Kate, GNOME Text Editor, gedit; `editorPresetsFor`,
   `EDITOR_PRESET_ARGS`) über `PATH` – heute meldet `resolveEditorExecutable` für sie `EDITOR_NOT_FOUND`, `editor.detect`
   kennt nur Notepad++/VS Code; ein Preset, das die Plattform nicht anbietet (`notepadpp` unter Linux), gilt als
   `system`; `spawnGui` (WP-103);
   Standardprogramm `xdg-open` (nur `isDefaultProgramAllowed(path, POSIX_PATHS)`); „Im Ordner zeigen“ über D-Bus
   `org.freedesktop.FileManager1.ShowItems` (`gdbus`), Rückfall `xdg-open <ordner>`; Links über `xdg-open`.
7. **Fähigkeiten:** `lib/platform.ts` gehört in L2 niemandem – die Werte für Linux (`externalConsole`, `shellWindow`,
   `editor`, `fileManager`, `autostart`, `protocolHandler`) liefert eine Funktion in `system/` (z. B.
   `linuxDesktopCapabilities()`), der Koordinator verdrahtet sie.
8. **Web:** `features/preferences/sections/FilesSection.tsx` (Editor-Vorgaben je Plattform), `features/files/lib/
   actions.ts`; Wörterbuch-Unterbaum `files`.

## Tests und Abnahme
- Windows unverändert grün (inkl. `system/**`, die unter Linux heute rot sind: dort Windows-Tests mit
  `runIf(win32)` bzw. Plattform-Naht). Linux im Container: `system/**`, `lib/chrome`, `launcher/chromeWindow`,
  `files/{editors,open}` grün; echte `notify-send`/Chrome-Aufrufe nur in `runIf(linux)`-Tests mit Fake-Programmen.
- Ressourcen und Bericht wie CLAUDE.md; Ergebnis unten in diesem Dokument.

## Ergebnis

### Umsetzung
1. **Chrome:** `findChromeLinux` (Einstellung → `google-chrome-stable`, `google-chrome`, `chromium`, `chromium-browser`
   auf `PATH` → `/snap/bin/chromium`), Version per `--version` (`parseChromeVersion`, `readChromeVersion` je
   Plattform). `chromeAppArgs` setzt unter Linux `--class=parallax` (`CHROME_WM_CLASS`, passend zu
   `StartupWMClass` der `.desktop`-Einträge). Snap-Chromium bekommt sein Profil in
   `~/snap/chromium/common/parallax-<16 hex des Datenordners>` statt `<home>/chrome`; alle Profil-Funktionen nehmen
   dafür optional `chrome`/`env`. Windows unverändert.
2. **Benachrichtigungen** (`lib/toast.ts`): Linux-Zweig hinter `createLinuxNotifier` – ohne grafische Sitzung und
   Session-Bus dauerhaft aus; mit Launch-URI ein wartendes `notify-send --print-id --action=default=<Öffnen> --wait`
   (Klick → `xdg-open parallax:…`, Warter mit Höchstalter 30 min, beim Ersetzen/Entfernen beendet), sonst
   `notify-send --print-id`, Rückfall D-Bus `org.freedesktop.Notifications.Notify` über `gdbus`; Ersetzen über
   `--replace-id`, Entfernen über `CloseNotification`. `ServiceUnknown`/fehlendes `gdbus` → dauerhaft, Timeouts →
   vorübergehend. `nativeToasts.ts`: Beschriftung „Öffnen“/„Open“ (`actionLabel`), neutrale Log-Texte.
3. **Systemintegration** (`system/xdg.ts`, `index.ts`, `installation.ts`, `markers.ts`): `IntegrationOps` je
   Plattform (Windows `.lnk` + Registry wie bisher, Linux `.desktop` + `xdg-mime`), dieselben Marker-Regeln
   (`launcher/main.ts`, `/start.mjs`) und derselbe ADR-229-Fingerabdruck (Größe/Version der Datei). Autostart
   `$XDG_CONFIG_HOME/autostart/parallax.desktop`, Handler `parallax-url-handler.desktop` + `xdg-mime default`
   (fremder Standard bleibt, `FOREIGN_ENTRY`), Programmeintrag `parallax.desktop` mit `<root>/parallax.svg` nur für
   eine Installation; Deinstaller entfernt nur die Einträge dieser Installation. `Exec` nach Desktop Entry Spec
   (Quoting, `%%`, Steuerzeichen abgelehnt). Pfade nur aus `HOME`/`XDG_*` der übergebenen Umgebung.
4. **Konsole** (`system/terminalEmulator.ts`, `linuxConsole.ts`, `platform.ts`): Emulator nach Einstellung →
   `xdg-terminal-exec` → `x-terminal-emulator` → bekannte, je eigene Syntax; die Konsole wird in `/proc` gesucht
   (Prozess des Nutzers mit `PARALLAX_ENTRY_ID`, passendem `argv[0]`, Start nach dem Klick), sonst der Emulator
   selbst; `state()` ist die Windows-Prüfung über `/proc` (`createConsoleStateCheck`). Shell-Fenster (ohne
   Entry-ID) → `opened` ohne PID. `createPlatformConsoleLauncher` wählt je Plattform, ohne grafische Sitzung `null`.
5. **Externe Konsole:** `consoleCommandFor(spec, platform)` – unter Linux `cd -- <cwd> && PARALLAX=1
   PARALLAX_ENTRY_ID=… NAME=… <exe> <args>` mit POSIX-Quoting (`posixShellWord`, `$'…'` für Steuerzeichen),
   Geheimnisse als `stty -echo`-Abfrage (`posixSecretPrompt`), ungültige Namen über `env --`. Ohne Emulator lehnt
   ein Preflight (`withConsolePreflight`/`consolePreflight`, Port unverändert) **vor** dem Schließen der
   SDK-Abfrage ab (`EXTERNAL_CONSOLE_FAILED`, Session läuft weiter).
6. **Editor und Dateien:** Linux-Vorgaben über `PATH` (`LINUX_EDITOR_NAMES`, z. B. `zed`/`zeditor`, `subl`,
   `gnome-text-editor`), `effectiveEditorPreset` (nicht angebotenes Preset wie `notepadpp` → `system`),
   `resolveEditorExecutable` lehnt nicht angebotene Presets ab. `open.ts`: Standardprogramm/`system` per `xdgOpen`
   nach `isDefaultProgramAllowed(…, POSIX_PATHS)` (Pfad und realer Pfad), Editor per `spawnGui`, „Im Dateimanager
   zeigen“ per `gdbus` `org.freedesktop.FileManager1.ShowItems`, Rückfall `xdg-open <ordner>`
   (`system/desktop.ts`). Links (`linkCommands.ts`) unter Linux per `xdg-open` (nur http(s)).
7. **Fähigkeiten:** `linuxDesktopCapabilities()` in `system/platform.ts` (Sitzung, Emulator, `xdg-open`, `gdbus`,
   `xdg-mime`, `HOME`); verdrahtet der Koordinator.
8. **Web:** `FilesSection.tsx` zeigt ein auf dem Host nicht angebotenes Preset als „Standardprogramm“ (kein
   Schein-Änderungszustand), Linux-Texte `files.posix.editorHint`/`blockedIssue` (en/de). `features/files/lib/
   actions.ts` brauchte nichts – WP-104 hat die Fähigkeiten und „Dateimanager“ schon eingebaut.

### Entscheidungen
- Die Linux-Konsolenzeile trägt `PARALLAX=1 PARALLAX_ENTRY_ID=…` (Auftrag Punkt 5); die Windows-Zeile bleibt ohne.
- Preflight statt Port-Änderung: eine `WeakMap`-Registry an der Launcher-Instanz; der Launcher-Port bleibt.
- `notepadpp` unter Linux behandelt `open.ts` als `system` mit Endungsprüfung, weil `files/service.ts` nicht zu
  WP-106 gehört (Follow-up).
- Toast-Klick unter Linux öffnet die `parallax:`-URI per `xdg-open` (der Handler ist nur mit „Öffnen beim Klick“
  registriert) – derselbe Weg wie der Windows-Toast.

### Abweichungen und Stolpersteine
- Das Abzeichen „Standard“ der Editor-Vorgaben bleibt bei Notepad++ (Windows); unter Linux ohne Abzeichen, sonst
  bricht der exakte Namensvergleich in `host-platform.test.tsx` (nicht WP-106).
- `system/console.test.ts` erwartete unter Linux `unknown` für die native Startzeit; seit WP-103 liest Linux sie
  aus `/proc` – Erwartung angepasst.
- Windows-Tests in `system/**` mit echtem Temp-`APPDATA` laufen nur unter Windows (`runIf`), die Plattform-Naht
  (`platform: 'win32'`) deckt den Rest auf beiden Systemen.
- `guard.test.ts` prüft zusätzlich, dass Linux ohne Injektion weder `xdg-mime` noch das Dateisystem anfasst und
  jeder Test der Linux-Integration `memoryDesktopFs` nimmt.

### Prüfungen
`tsc -b` sauber; ESLint und `prettier --check` der geänderten Dateien sauber; gezielte Tests unter Windows
(System, Chrome, Toasts, Editor/Dateien, Links, Konsole, externe Konsole und abhängige Integrationstests, Web
`FilesSection`/`host-platform`) und im Linux-Container (28 Dateien) grün; `public-check` 0 Funde.
