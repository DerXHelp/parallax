### Anforderungen (normativ)
1. **Zugriffsrichtlinie (ADR-141, §4.12 Prüfkette in genau dieser Reihenfolge):** (1) Stringfilter →
   `PATH_REJECTED{reason}`; (2) Vorprüfung am String: Schlüssel unter einer Wurzel (`cwd`,
   `additionalDirectories`, Anhangordner) oder exakt im Index → sonst `PATH_NOT_ALLOWED` **ohne**
   fs-Aufruf; (3) `lstat`/`readlink` je Segment unterhalb der Wurzel (unsicheres Ziel →
   `PATH_REJECTED{reason:'link_target'}`); (4) `realpath` + Stringfilter; (5) Richtlinie auf dem
   Ziel (Wurzeln selbst `realpath`-normalisiert, Cache je Eintrag, verworfen bei Profiländerung bzw.
   nach 60 s). Jeder fs-Aufruf mit 3 s Timeout → `FILE_NOT_READABLE{reason:'timeout'}`;
   `ENOENT` → `FILE_NOT_FOUND`; `EACCES`/`EPERM`/`EBUSY` → `FILE_NOT_READABLE`. Eine Funktion für
   alle Wege (Befehle, HTTP, Öffnen); `lib/paths.ts` `resolveAllowedPath` wiederverwenden bzw.
   erweitern, nichts duplizieren.
2. **`file.stat`/`file.statMany`:** Typ per Magic-Bytes (png, jpeg, gif, webp, bmp, ico, pdf), `svg`
   per Endung, sonst Text-Erkennung auf den ersten 64 KiB (BOM UTF-8/UTF-16LE/BE, gültiges UTF-8,
   NUL-Anteil → `binary`, Rückfall `windows-1252`), `markdown` für `.md`/`.markdown`; Ordner →
   `directory`. `previewable`, `truncated`, `mediaType`, `access` nach §4.5. `statMany`: Reihenfolge
   wie angefragt, je Pfad `ok:false` statt Ausnahme, höchstens 8 parallel, ≤ `fileStatBatchMax`.
3. **`GET`/`HEAD /api/file`** (`FileContentProvider.open`): Text nach UTF-8 gewandelt, über
   `fileTextBytes` am letzten Zeilenende davor gekürzt; Bild/PDF als Stream ≤ `fileBinaryBytes`
   (sonst `PAYLOAD_TOO_LARGE`); `binary`/`directory` → `UNSUPPORTED_MEDIA_TYPE`. Header genau nach
   §4.8 (`no-store`, `inline; filename*=`, CORP, CSP `BLOB_CSP` + XFO `DENY` bzw. `FILE_PDF_CSP` +
   XFO `SAMEORIGIN`). Guard-Klasse `file` in `http/origin.ts`: Cookie, `Sec-Fetch-Site` **Pflicht**
   `same-origin` (fehlend, `same-site`, `cross-site`, `none` → abgelehnt), `Origin` falls vorhanden ∈
   `allowedOrigins`. Fehlerkörper `ErrorPayload`, Status aus `ERROR_CATALOG`. Logs ohne Dateiinhalt.
4. **Blob-PDF:** `GET /api/blob/:id` mit Meta `application/pdf` (und `%PDF-`-Body) → Header-Satz `pdf`.
5. **Upload (`POST /api/attachments`):** Header-`Content-Type` ∈ `UPLOAD_MEDIA_TYPES`; Typ per
   Magic-Bytes: Bild wie bisher (≤ `imageBytes`), `%PDF-` → `application/pdf` (≤ `pdfBytes`), sonst
   `application/octet-stream` (≤ `fileAttachmentBytes`, `name` Pflicht, sonst `VALIDATION_FAILED`);
   `bodyLimit` = größtes dieser Limits; Antwort wie bisher.
6. **`AttachmentFileStore`** (`store/attachments.ts`): `dir` = `<home>\entries\<entryId>\attachments`
   (bei Bedarf angelegt); `materialize` kopiert den Blob nach `<dir>\<blobId[0..16]>\<name>`
   (idempotent: existiert mit gleicher Größe → nichts tun), Name bereinigt (verbotene Zeichen,
   Punkt/Leerzeichen am Ende, reservierte Namen, Länge ≤ 120; Ergebnis muss `windowsPathIssue` = `null`
   haben, sonst `<blob16>.<ext>`), `BLOB_NOT_FOUND` bei fehlendem Blob; atomar (`writeFileAtomic`).
7. **Datei-Index (ADR-145):** `observeOps` wertet `item.upsert` von `tool_call` mit Status `done`
   aus (`Read` → `read`, `Write` → `written`, `Edit`/`MultiEdit`/`NotebookEdit` → `edited`,
   `ExitPlanMode` `planFilePath` → `plan`, `task.outputFile` → `output`; Felder `file_path`/
   `notebook_path`), nur absolute Pfade mit Stringfilter; entprellt 2 s nach `files.json` (zod,
   atomar), ≤ `sessionFilesMax`, `flush()`. Backfill einmal aus den Transkript-Logs (alle
   `conversationIds`), danach `backfilled: true`. `files.session` ergänzt Dateien im Anhangordner als
   `attached`, sortiert nach `lastAt` absteigend. Keine Contract-Typen der SDK-Tools – Input tolerant
   mit zod lesen.
8. **`files.project` (ADR-151):** `cwd` existiert (`CWD_NOT_FOUND`); git per `resolveExecutable`,
   Argumente `-c core.fsmonitor=false -c core.quotepath=off ls-files -z --cached --others
   --exclude-standard`, `windowsHide: true`, ohne Shell, Timeout 5 s, Ausgabe ≤ 8 MB; kein Repo/Fehler
   → Walk (keine Links/Junctions, Ignore-Liste, Tiefe ≤ 12, 3 s); ≤ `projectFilesMax`, `truncated`,
   `source`; Cache je Eintrag 30 s, verworfen beim nächsten `observeOps` mit `Write`/`Edit`.
9. **`spawnGui` (`lib/process.ts`, ADR-144):** nur absolute `.exe` (`assertSpawnableFile`), Basisname
   ∉ `EDITOR_BLOCKED_EXECUTABLES` (case-insensitiv), PE-Prüfung (`MZ` → `e_lfanew` → `PE\0\0` →
   Optional-Header-Subsystem = 2, sonst `OPEN_FAILED{reason:'not_gui'}`), `shell:false`,
   Argument-Array, `windowsHide:false`, `detached:true`, `stdio:'ignore'`, `unref()`, `cwd` = Ordner

   Kopfkommentar verweist auf die Ausnahme von der Windows-Regel (Vorschlag WP-50 §6).
10. **`file.open` (§4.12):** Richtlinie wie Punkt 1. `editor`: nur Dateien (`VALIDATION_FAILED

    HKLM: `notepad++.exe`, `Code.exe`) bzw. Uninstall-`InstallLocation` → Standardpfade

    Microsoft VS Code\Code.exe`, `%ProgramFiles%\Microsoft VS Code\Code.exe`); nicht gefunden →

    Argument ersetzt (`line`/`col` fehlen → 1), kein Zusammenfügen zu einer Kommandozeile; `system`

### Umsetzung je Anforderung
1. **Zugriffsrichtlinie (`lib/paths.ts`).** `resolveAllowedPath(file, policy, options)` ersetzt die
   alte Signatur `(file, roots[], fs)`; bisher hatte nur ein Test sie aufgerufen.
   - `AccessPolicy`:
     - `roots` in Prioritätsreihenfolge; `kind` wird zu `FileInfo.access`.
     - `listed`: Schlüssel aus dem Session-Index, geladen nur, wenn keine Wurzel passt.
   - Die Prüfkette läuft genau in der Reihenfolge 1–5.
     - Stufe 2 vergleicht nur Strings, also die Wurzel-Strings und nicht deren `realpath`; ein
       abgelehnter Pfad löst keinen fs-Aufruf aus.
   - Neue Funktionen: `physicalPath` (Stufen 3 und 4), `physicalRoot` und `fileAccessError`.
   - Fehlerabbildung in `fileAccessError`:
     - `ENOENT`/`ENOTDIR` → `FILE_NOT_FOUND`;
     - `EACCES`/`EPERM` → `FILE_NOT_READABLE{access}`;
     - `EBUSY` → `FILE_NOT_READABLE{busy}`;
     - Timeout → `FILE_NOT_READABLE{timeout}`.
   - 3 s Timeout je fs-Aufruf: `lib/fsTimeout.ts` (`createFsCallGuard`) zusammen mit
     `files/fileFs.ts` (`guardFileFs`).
   - Wurzel-Cache je Eintrag im Dienst:
     - Schlüssel ist die Signatur aus cwd und add-dirs; eine Änderung verwirft den Cache sofort.
     - Ein Eintrag gilt 60 s.
2. **`file.stat`/`file.statMany` (`files/stat.ts`).**
   - Typerkennung per Magic Bytes in `lib/sniff.ts`.
     - BMP nur mit gültiger DIB-Größe und Reserve = 0, ICO nur mit mindestens einem Bild; sonst würde
       Text wie „BMW …“ als Bild erkannt.
   - Text-Erkennung in `lib/textDecode.ts`.
   - `statMany` läuft über `lib/pool.ts` (`mapPool`, höchstens 8 parallel), hält die angefragte
     Reihenfolge ein und liefert `ok:false` je fehlerhaftem Pfad.
3. **`GET`/`HEAD /api/file` (`files/content.ts`, Route in `http/app.ts`).**
   - Die Route ist per `app.route` für GET und HEAD registriert; HEAD verwirft den Stream.
   - Text wird dekodiert, als UTF-8 ausgeliefert und am letzten `\n` vor `fileTextBytes` gekürzt.
   - `http/origin.ts` bekommt die Guard-Klasse `file`.
   - `X-Frame-Options` setzt der onSend-Hook nur noch, wenn die Route keinen Wert gesetzt hat
     (PDF: `SAMEORIGIN`).
   - Exporte: `contentPolicyHeaders`, `inlineDisposition`.
     - `inlineDisposition` liefert RFC 5987 `filename*` und kodiert auch `'()*`; ein leerer Name wird
       zu `file`.
4. **Blob-PDF.** `isPdfBlob(ref, data)` prüft Meta `application/pdf` **und** `%PDF-`-Körper; dann
   gilt der PDF-Header-Satz.
5. **Upload.**
   - Content-Type-Parser für `UPLOAD_MEDIA_TYPES` mit `bodyLimit = UPLOAD_BODY_LIMIT_BYTES` (das
     größte Typ-Limit).
   - Das Limit des erkannten Typs gilt danach (413); die Pixelgröße wird nur für Bilder gespeichert.
   - `store/blobs.ts`: `%PDF-` gilt als bestätigter Typ.
6. **Anhang-Store (`store/attachments.ts`).** `createAttachmentFileStore(home, blobs, {fs?, sizeOf?})`
   mit den Exporten `attachmentsDir` und `sanitizeAttachmentName`.
7. **Datei-Index (`files/sessionIndex.ts`).**
   - Gespeichert in `entries/<id>/files.json` über JsonStore.
   - Je Tool-Call wird nur einmal gezählt (Re-Upsert, Neustart).

   - `parseLsFiles` verwirft bei abgeschnittener Ausgabe den unvollständigen letzten Pfad.

   - Cache 30 s je Eintrag und cwd; `observeOps` mit `wroteFiles` verwirft ihn.
   - Ein UNC-cwd wird mit `PATH_REJECTED` abgewiesen, bevor irgendetwas auf das Dateisystem zugreift.
9. **`spawnGui` (`lib/process.ts`, ADR-144).**

### Abweichungen und Entscheidungen
- **`deps.attachments` gibt es nicht.** Der Dienst bildet den Anhangordner mit `attachmentsDir(home,
  entryId)` aus `store/attachments.ts` (rein, ohne fs) und braucht daher nur `home`. Das Anlegen des
  Ordners bleibt beim `AttachmentFileStore` der Engine.
  - Fehlt der Ordner, zählt die Wurzel einfach nicht: `physicalRoot` liefert `null` und es wird nichts
    gecacht.
- **Upload:**
  - Ein deklariertes Bild oder PDF muss zu den Magic Bytes passen, sonst 415.
  - Bei `application/octet-stream` entscheiden die Magic Bytes allein: Bild, PDF, sonst Datei.
  - Ein leerer Körper ist immer 415.
  - `name` ist nur für Dateien Pflicht (`VALIDATION_FAILED{reason:'name'}`).
- **Hängendes Laufwerk.** Läuft auf einem Laufwerk ein abgelaufener fs-Aufruf noch, scheitert jeder
  weitere Aufruf dort sofort mit Timeout und wird nicht eingereiht; libuv hat nur vier Threads.
- **Wurzel-Cache.** Fehlende Wurzeln werden nicht gecacht; ein später angelegter Anhangordner zählt
  sofort.

### Stolpersteine
- **Zugeordnete Netzlaufwerke:** `realpath` liefert dort `\\server\share\…`. Weil der Segment-Walk
  keinen Link dorthin gefunden hat, bleibt der Laufwerkspfad stehen (ADR-119/141). Erkannt wird das
  nur am String; ein Test mit einem echten Netzlaufwerk fehlt.
- **Index-Treffer werden am Ziel per Schlüssel geprüft.** Ein im Index stehender Pfad, der auf eine
  andere Datei verlinkt, wird abgelehnt (gewollt). Ein Index-Pfad mit 8.3-Kurznamen außerhalb der
  Wurzeln wird ebenfalls abgelehnt (`realpath` expandiert ihn).
- **TOCTOU** zwischen Prüfung und Öffnen bzw. Start wird hingenommen: lokaler Einzelnutzer, die
  Prüfung läuft unmittelbar davor.
- **Text-Erkennung:**
  - `truncated` ist bei Texten, die nicht UTF-8 sind, eine Schätzung: die Kürzung zählt die
    UTF-8-Bytes nach dem Umkodieren.
  - Schon **ein** NUL-Byte macht eine Datei binär; UTF-16 ohne BOM gilt daher als binär.
