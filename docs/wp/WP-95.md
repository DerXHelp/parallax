# WP-95 – Interne CLI-Nachrichten statt „Unknown event“

Koordinator, Branch `feature/cli-nachrichten`. Auftrag des Nutzers am 20.11.2026.

## Auftrag
„Ich bekomme beim Arbeiten auf einer anderen Kiste häufig im Laufen eine Nachricht ‚unknown event
system/permission_check_status‘ – was ist das?“ Danach: „Wir sollten direkt eine saubere Lösung einfügen. In diesem
Zusammenhang prüfe bitte, was es da noch für Nachrichten gibt, welche wir unterstützen müssen.“ Dazu: Das Echo von
`/rename` wirkte im Transkript, als hätte der Nutzer es geschrieben.

## Bestandsaufnahme (CLI 2.1.323, SDK 0.3.322)
- Die **öffentliche** `SDKMessage`-Union des SDK deckt der Normalizer vollständig ab.
- Die Meldungen kommen aus **internen** Systemnachrichten (`@internal` in den Schemas des `claude`-Binarys, „not yet
  in the public SDKMessage union“), die `claude` im SDK-Modus trotzdem schickt.
- Zähler der produktiven Instanz (nur gelesen, alle Einträge): `system/permission_check_status` 94×,
  `system/vcs_state_changed` 6×, sonst nichts Unbekanntes.
- Einordnung je Nachricht anhand der Schema-Beschreibung und der Sendestelle im Binary (`Ws({...})` = Ausgabe an den
  SDK-Host, `this.emit` im Print-Modus):

| Nachricht | Bedeutung | Regel |
|---|---|---|
| `permission_check_status` | Auto-Mode-Classifier hält einen Tool-Aufruf > ~4 s auf (`checking` … `done`) | Feld `tool_call.permissionCheck`, Hinweis an der Tool-Zeile |
| `model_fallback` | Turn läuft auf dem Ausweichmodell (überlastet, Modell weg …) | Item `system/model_fallback` |
| `model_consent_fallback` | Zustimmungs-Dialog (z. B. Nutzungsguthaben) wechselt das Modell | Item `system/model_fallback` |
| `file_attachments_missing` | Dateien einer Nachricht aus Remote Control / Claude Code Remote kamen nicht an | neues Item `system/attachments_missing` |
| `peer_message_hold` | Nachricht einer anderen Session von der Empfangsregel zurückgehalten → freigegeben/verworfen | neues Item `system/peer_message_hold` (Upsert je Nachricht) |
| `vcs_state_changed` | Commit, Push, Merge, Rebase in der Shell | Signal `vcs_changed` → Git-Branch neu lesen |
| `dev_intent`, `instruction_size_warning`, `feedback_draft_queued`, `code_change_published`, `per_turn_effort_changed` | Hinweise für andere Hosts (Desktop, iOS-Simulator, Feedback-Karte), PR-Link (steht in der Tool-Ausgabe), Effort (kommt mit `init`) | ignoriert (`ignoredCounts`) |
| `session_metadata`, `cloud_session_delta`, `inherited_asks_settled`, `turn_handoff_available`, `upgrade_relay_marker` | Cloud-Worker-Interna | ignoriert |
| `turn_preempted` | nur mit Opt-in im Initialize (Parallax meldet es nicht an) | bleibt unbekannt |
| `turn_duration`, `stop_hook_summary`, `agents_killed`, `away_summary`, `memory_saved`, `permission_retry`, `scheduled_task_fire`, `file_snapshot`, `thinking`, `api_error` | REPL-intern bzw. Draht-Zwilling `api_retry` | bleibt unbekannt (käme es doch, zeigt die ruhige Zeile die Änderung) |

Nicht Teil dieses WP: `request_user_dialog` (`onUserDialog`, z. B. Rückfrage beim Refusal-Fallback). Ohne
angemeldete Dialogarten verhält sich `claude` wie ohne Dialog – kein Hänger, mögliches eigenes Vorhaben.

## Umsetzung (ADR-236)
- **Contract** (`src/shared/model.ts`, `protocol.ts`, `samples.ts`): `ToolCallItem.permissionCheck` (Default `false`),
  System-Events `attachments_missing` und `peer_message_hold`, `PROTOCOL_VERSION` 6. Port `StatusSignal`
  `vcs_changed` (`sessions/ports.ts`), Status-Maschine ignoriert es.
- **Normalizer** (`normalizer/live.ts`, `sdk-schemas.ts`): tolerante Schemas der fünf Nachrichten; `checking` setzt
  das Feld nur ohne Ergebnis, `done` und jedes Tool-Ergebnis löschen es; unbekannter Aufruf → gezählt
  `system/permission_check_status:unmatched`, unbekannter Status → `unknownCounts`. `file_attachments_missing` ohne
  fehlende Datei → gezählt-ignoriert. `peer_message_hold` behält Name und Grund, wenn ein späterer Frame sie nicht
  wiederholt. Zehn Subtypen neu in `IGNORED_SYSTEM_SUBTYPES`.
- **Engine** (`runtime.ts`): `vcs_changed` → `refreshGitBranch()` (eine Abfrage zur Zeit, wie ADR-113).
- **Fake** (`backend/fake/cliNotices.ts`): `fake:cli-notices` spielt alle angezeigten Nachrichten ab.
- **Web** (`features/transcript/**`): siehe unten.

## Web
- **Tool-Zeile** (`ToolCallRow.tsx`): Bei `permissionCheck` und Status `streaming_input`/`pending`/`running` steht
  „Berechtigung wird geprüft…“ mit pulsierendem Schild-Icon in der Zeile, ohne eigene Zeile. So springt nichts, wenn
  die Prüfung endet. Die Gruppenzeile der Kompaktansicht sagt für den laufenden Schritt „prüft Berechtigung: …“
  (`StepGroupRow.tsx`, `isCheckingPermission` in `lib/grouping.ts`).
- **System-Zeilen** (`SystemRow.tsx`):
  - `attachments_missing` erscheint als Warnung („1 von 2 angehängten Dateien kam nicht an“ / „Claude macht ohne sie
    weiter.“).
  - `peer_message_hold` ist eine ruhige Zeile mit eigenem Icon je Zustand: zurückgehalten (mit übersetztem Grund),
    durchgelassen, nicht zugestellt (mit übersetztem Ergebnis). Unbekannte Werte erscheinen roh.
- **Rollen** (`lib/grouping.ts`): Alle System-Events stehen jetzt in einem `Record` (`SYSTEM_EVENT_ROLES`). Ein neues
  Event braucht so eine Entscheidung, sonst meldet der Compiler einen Fehler. Beide neuen Events sind sichtbar.
- **`/rename`** (`lib/rename.ts`, `MessageRows.tsx`):
  - Eine `user_message` mit `/rename <Titel>` wird zur ruhigen Zeile „Titel an Claude Code übergeben: …“. In der
    Claude-App getippt heißt sie „In der Claude-App umbenannt: …“. Ein wartender `/rename` in der Queue erscheint als
    dieselbe Zeile, abgeblendet.
  - Die Antwort der CLI ist versteckt (`itemCodesById`): live der lokale Befehl `rename`, im Verlauf die
    `local_command_output` direkt danach.
- Texte stehen im Lazy-Wörterbuch `features/transcript/i18n-lazy/{en,de}.ts` (Budget des Start-Chunks).

## Prüfungen
- Unit- und Integrationstests:
  - Normalizer: 6 neue Fälle in `live.test.ts`.
  - `fake:cli-notices`: `interactive.test.ts`.
  - Engine: Git-Branch nach `vcs_state_changed` in `phase2.integration.test.ts`. Der Fall schlägt ohne die
    Engine-Zeile fehl.
  - Web: `cli-messages.test.tsx`, `rename.test.ts`, `grouping.test.ts`.
- 17 Snapshots aktualisiert; einzige Änderung ist `"permissionCheck": false` an Tool-Aufrufen.
- E2E `e2e/wp95-cli-notices.spec.ts`:
  - `fake:cli-notices`: Hinweis während der Prüfung, danach weg; Fallback, fehlende Datei, nicht zugestellte
    Nachricht; kein „Unknown event“.
  - `/rename` bei laufendem Prozess: ruhige Zeile, keine Sprechblase, kein „Session renamed to“.
- Keine Live-Prüfung: Die langsame Classifier-Prüfung lässt sich nicht gezielt auslösen. Die Formen stammen aus den
  Schemas des installierten `claude` und aus den Zählern der produktiven Instanz.

## Offen
- `request_user_dialog` (Dialoge der CLI, z. B. beim Refusal-Fallback) – eigenes Vorhaben, falls gewünscht.
- Agent- und Plan-Karten zeigen den Prüfhinweis nicht (eigene Zeilen-Komponenten).
- Die Übersetzungen der `cause`-/`outcome`-Werte von `peer_message_hold` sind aus den Namen abgeleitet. Sie sind noch
  nicht an echten Daten geprüft.
