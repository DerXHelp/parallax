## 2. Bestand (Erkundung 21.11.2026)

- **Session-Modell:** `entrySchema` (`src/shared/model.ts` ~1490–1550), `cwd` exakt gespeichert, Gruppierung der
  Seitenleiste nach `pathKey(hostId, cwd)` (`src/web/lib/session-order.ts`), Persistenz `sessions.json`.
  `session.create {cwd, profileId?, model?, permissionMode?, effort?, prompt?}` → `checkCwd` → `startRuntime`.
- **Git:** nur `sessions/lib/gitBranch.ts` (`git rev-parse --abbrev-ref HEAD`, Fallback `git branch --show-current`;
  kein Watch auf `.git/HEAD` – `docs/plan.md` Phase 1 beschreibt mehr) und `git ls-files` für den @-Picker.
  `git` kommt über `resolveExecutable('git', env)` (absolute `.exe`) und `runFile` (ohne Shell, 5 s).
- **Worktrees:** nicht erkannt; `-w/--worktree` ist in den Profil-Argumenten gesperrt (`claude/profileArgs.ts`).
- **Diffs:** nur aus Edit/Write-Aufrufen (`web/lib/diff.ts`, `ui/diff-view.tsx`: unified, 300 Zeilen, nicht
  virtualisiert). Index „Dateien dieser Session“ aus Tool-Aufrufen (`server/files/sessionIndex.ts`,
  `entries/<id>/files.json`).
- **Plan-Kommentare (WP-93):** `text-anchor.ts` (generisch), Formatierung `web/lib/plan-feedback.ts`, Highlights über
  die CSS Custom Highlight API; `PlanAnnotator` selbst hängt an Plan-Blöcken.
- **Composer:** Paste-Chips (`DraftPaste`), von außen über `setDraft(sessionKey, text, pastes)`; `promptChars` 200 000,
  `pastesMax` 20. Ein Review-Paket als Chip braucht keinen Contract.
- **Seitenpanel:** feste Liste `SIDE_PANEL_TABS` (`shell/requests.ts`), Inhalt per `switch` in `SidePanelFrame.tsx`.
- **Suche:** Strg+K nur Titel/Ordner/Branch/Profil, ohne Archiv. Eigene Transkriptkopien
  `entries/<id>/<conversationId>.transcript.jsonl` (`server/store/transcripts.ts`).
- **Seitenleiste:** Anheften gibt es (`session.setPinned`); `unread` setzt der Server bei `turn_result` ohne sichtbares
  Fenster; Benachrichtigungen nur global je Ereignisart plus „Nicht stören“.
- **Ruhezustand gibt es** (`settings.idleSleep`, Standard an, 30 min, ADR-105; `manager.ts` ~598–639). Angeheftet
  spielt dabei keine Rolle.
- **Elicitation:** Parallax setzt kein `onElicitation` → das SDK lehnt jede Anfrage still ab. SDK 0.3.322:
  `ElicitationRequest {serverName, message, mode?: 'form'|'url', url?, elicitationId?, requestedSchema?, title?,

- **Fenster:** Chrome im App-Modus mit eigenem Profil (`launcher/chromeWindow.ts`, ADR-136); Auth über Launcher-Code
  → `#code=…` → Cookie `parallax_<port>`; Origin genau `http://127.0.0.1:<port>`. Server läuft unsichtbar weiter,
  wenn das Fenster zu ist. Fenstertitel „(n) Parallax“ ist die einzige Zähleranzeige. Paket heute 13,4 MB Zip.
  WP-83 schloss `.exe`/MSI und Authenticode für v1 aus (SmartScreen/AppLocker); `docs/plan.md` verlangt: keine
  Downloads per `postinstall` von GitHub, Electron als eigenes Workspace-Paket.

## 3. Design

### 3.1 Git-Dienst (Server, Grundlage für F1–F4)
- Neues Modul `src/server/git/**`: ein Läufer über `runFile` mit dem absoluten `git` aus `resolveExecutable` (PATH der
  Session), Argument-Arrays, Pfade immer nach `--`, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0` für lesende Aufrufe.
- **Härtung:** Lesende Aufrufe (`status`, `diff`, `log`, `rev-parse`, `worktree list`) laufen mit
  `-c core.fsmonitor=false` – sonst könnte ein fremdes Repo über seine Konfiguration ein Programm starten. Schreibende
  Aufrufe (Commit) führen die Hooks des Repos aus wie im Terminal.
- Timeouts: lesend 10 s, `worktree add` und `push` 120 s; Ausgabegrenzen je Aufruf (Diff je Datei 1 MiB, höchstens
  500 Dateien, Binärdateien nur als „binär“).
- Operationen: `status` (porcelain v2, `-z`, Branch, ahead/behind), `diff` (Liste mit numstat, Patch je Datei), `commit`
  (Nachricht; alle Änderungen oder ausgewählte Dateien), `branchCreate`, `branchSwitch` (nur ohne Konflikt; sonst
  Fehler mit Hinweis), `push` (ohne Upstream `-u origin <branch>`). Schlägt Push an der Anmeldung fehl: Fehler
  `GIT_PUSH_FAILED {reason: 'auth'}` und Knopf „Im Terminal pushen“ (öffnet ein Terminal mit `git push`).
- Gilt für Sessions anderer Rechner genauso: Die Befehle gehen an den Server des Rechners der Session.

### 3.2 Worktrees (F2)
- **Optional:** In „Neue Session“ erscheint der Schalter „In eigenem Worktree“ nur, wenn der Ordner in einem Git-Repo
  liegt; Standard aus (je Projekt merkbar). Felder: Branch-Name (vorbelegt aus dem Titel bzw. `parallax/<kurz-id>`),
  Basis (Standard: aktueller Branch des Haupt-Worktrees). Alternativ „vorhandenen Worktree wählen“
  (`git worktree list`).
- **Ort wie Claude Code:** `<repo>/.claude/worktrees/<name>` (dieselbe Konvention wie `claude --worktree`), damit
  „Im Terminal fortsetzen“ und Claudes eigene Werkzeuge denselben Ordner sehen. Ist der Ordner nicht ignoriert, trägt
  Parallax ihn in `.git/info/exclude` ein (lokal, ändert keine Datei im Repo).
- `.worktreeinclude` (Konvention von Claude Code, `.gitignore`-Syntax): passende **ignorierte** Dateien (z. B. `.env`)
  werden in den neuen Worktree kopiert.
- Anlegen läuft asynchron mit Zustand „Worktree wird angelegt …“; die Session startet danach mit `cwd` = Worktree-Pfad
  (exakter String). Neue Felder am Eintrag: `worktree {repoRoot, path, branch, baseRef, baseSha, portBase} | null`.
- **Seitenleiste:** Worktree-Sessions gruppieren unter dem Projekt des Haupt-Repos (`repoRoot`), mit Branch-Kennung –
  nicht als eigenes Projekt je Worktree.
- **Aufräumen:** Beim Archivieren oder Entfernen einer Worktree-Session prüft der Server uncommittete Änderungen und
  Commits, die in keinem Remote-Branch und nicht in der Basis enthalten sind. Dialog: „Worktree behalten“ (Standard,
  wenn etwas offen ist), „Worktree löschen, Branch behalten“, „Worktree und Branch löschen“ (bei offener Arbeit nur nach
  ausdrücklicher Bestätigung). `git worktree remove [--force]`, `git branch -d|-D`.
- Windows: lange Pfade (`core.longpaths` wird nur gelesen und bei Bedarf als Hinweis gemeldet, nicht gesetzt).

### 3.3 Setup, Teardown, Ports (F3, optional je Projekt)
- **Projekt-Einstellungen** (lokal in `settings.json`, je Rechner, Schlüssel = Repo-Wurzel nach Pfadregeln):
  Setup-Befehl, Teardown-Befehl, Shell (Standard aus „Konsole“), Portbereich an/aus, Worktree-Standard an/aus. Leer =
  nichts passiert. Die Befehle kommen nie aus dem Repo, nur vom Nutzer – kein Vertrauensproblem beim Öffnen fremder
  Repos. Für einen anderen Rechner nur mit der Stufe, die dessen Einstellungen ändern darf.
- **Setup** läuft nach dem Anlegen des Worktrees **sichtbar** in einem Terminal-Tab „Setup“ der Session: die gewählte
  Shell mit dem Befehl (`cmd /d /s /c`, `powershell -Command`, `bash -lc`). Das ist eine bewusste Ausnahme von „nie über
  eine Shell“ (ADR-251): nur vom Nutzer eingegebener Text, im Pseudoterminal sichtbar, abbrechbar. Ein Start-Prompt der
  Session wartet, bis Setup mit Exit 0 endet; sonst Karte „Setup fehlgeschlagen (Exit n)“ mit „Trotzdem starten“ und
  „Ausgabe ansehen“.
- **Teardown** läuft vor dem Löschen des Worktrees genauso; schlägt er fehl: „Trotzdem löschen“ / „Abbrechen“.
- **Portbereich:** Jeder Worktree bekommt einen freien Block von 10 Ports (ab 41000, Schritt 10, bis 49990, belegt
  bleibt er bis zum Löschen). `PARALLAX_WORKTREE_PORT=<basis>` steht im Prozess von `claude`, in Setup/Teardown und in
  den Terminals der Session. Das Projekt muss die Variable selbst nutzen (z. B. Vite-Port) – so machen es Conductor und
  Emdash. `buildEnv` setzt sie zusätzlich zu `PARALLAX`/`PARALLAX_ENTRY_ID` (Erweiterung ADR-083).

### 3.4 Session-Review (F1)
- Neuer Tab **„Änderungen“** im Seitenpanel (zusammen mit F4): oben Branch, ahead/behind und Aktionen, darunter die
  Dateiliste mit Status, darunter der Diff je Datei (einklappbar, Zeilennummern, virtualisiert ab 300 Zeilen, Link
  „Datei öffnen“).
- **Basis des Gesamt-Diffs:** Worktree-Session = Merge-Base mit `baseRef`; sonst `baseSha` = `HEAD` beim Anlegen der
  Session (neues Feld, alte Sessions: aktueller `HEAD`). Verglichen wird mit dem Arbeitsstand inklusive ungetrackter
  Dateien. Ohne Worktree ist der Filter „nur Dateien dieser Session“ (aus `files.json`) Standard, mit dem Hinweis, dass
  andere Sessions im selben Ordner mitschreiben können.
- **Kommentare:** Zeile überfahren → „+“, oder Zeilen markieren → `C`; Markdown-Text, Enter speichert, Esc bricht ab.
  Gespeichert auf dem Server (`entries/<id>/review.json`), synchron in allen Fenstern und über „Mehrere Rechner“.
  Verankert über Pfad, Seite, Zeile und Zitat; verschiebt sich der Diff, sucht `text-anchor` das Zitat neu, sonst gilt
  der Kommentar als „veraltet“ (bleibt sichtbar).
- **Senden:** „An Claude senden (n)“ baut eine nummerierte Liste (`pfad:zeile`, zitierte Zeilen, Kommentar) wie
  `plan-feedback.ts` und legt sie als Paste-Chip in den Composer der Session; der Nutzer ergänzt Text und sendet. Danach
  sind die Kommentare „gesendet“ (eingeklappt, wieder aufklappbar).

### 3.5 Git-Leiste (F4)
- Im Tab „Änderungen“: Commit-Feld (Nachricht, „Alle“ oder ausgewählte Dateien), Branch-Menü (anlegen, wechseln),
  „Push“ mit ahead-Zähler. Fehler zeigt die Leiste selbst (`Alert role="alert"`). Der Status aktualisiert sich nach
  jedem Turn-Ende, beim Öffnen des Tabs und nach jeder Aktion; dazu ein Watch auf `.git/HEAD` bzw. die `HEAD`-Datei des
  Worktrees (erfüllt nebenbei die alte Plan-Stelle).

### 3.6 Volltextsuche (F5)
- Server: Scan der eigenen Transkript-Logs (`*.transcript.jsonl`), Titel, Turn-Fazits und Pläne in einem Worker-Thread
  (kein Index in v1), Groß-/Kleinschreibung egal, Treffer mit Ausschnitt und Zeit, höchstens 200, neueste zuerst,
  abbrechbar. Durchsucht Prompts und Antworten; Werkzeugausgaben nur mit Schalter. Archivierte Sessions sind dabei.
- Web: Strg+Shift+F öffnet die Suche (Dialog mit Trefferliste, Filter Projekt/Archiv); in Strg+K ein Eintrag „In
  Inhalten suchen: …“. Ein Klick öffnet die Session und springt zum Treffer (Laden um das Item herum: neuer Port
  `readAround`). Sessions anderer Rechner: Die Anfrage geht an jeden verbundenen Rechner, die Treffer tragen die Farbe
  des Rechners.

### 3.7 Übersicht (F6)
- **Filter** über der Seitenleiste: „Wartet auf mich“, „Arbeitet“, „Ungelesen“, „Alle“, dazu ein Textfilter
  (Titel, Ordner, Branch). Nur im Client, gespeichert je Fenster wie die übrige Ansicht.
- **Als ungelesen markieren:** Menüpunkt und neuer Befehl `session.setUnread`; bleibt stehen, bis die Session wieder
  neu geöffnet wird (nicht sofort durch das offene Fenster gelöscht).
- **Projekt stummschalten:** Menü am Projektkopf; `notifications.mutedProjects` in `settings.json`; der Notifier
  schickt für diese Sessions keine Toasts und Töne; Glocke-aus-Symbol am Projektkopf. Status und Zähler bleiben.
- **Angeheftete schlafen nicht:** Der Ruhezustand überspringt angeheftete Sessions; Hinweis in den Einstellungen
  „Sessions“.

### 3.8 Elicitation (F7)
- `onElicitation` im SdkBackend → neue Entscheidungsart `elicitation` im Broker, nicht-modal wie Freigaben, mit Toast
  „wartet auf Eingabe“.
- **Formular:** unterstützt die MCP-Teilmenge (Objekt mit Feldern `string` inkl. `enum`/Format, `number`/`integer`,
  `boolean`, Pflichtfelder, Titel/Beschreibung); Prüfung mit zod vor dem Senden. Unbekannte Felder → Karte bietet nur
  „Ablehnen“ und zeigt den Grund.
- **URL-Modus:** zeigt Server, Nachricht und Ziel (nur http/https), „Im Browser öffnen“ über den bestehenden Link-Weg,
  dann „Fertig“ oder „Abbrechen“; `elicitation_complete` schließt die Karte.
- Antworten: Annehmen (mit Inhalt), Ablehnen, Abbrechen; Stop/Interrupt der Session bricht offene Anfragen ab.
  FakeBackend-Szenarien und Fixtures für beide Modi.

### 3.9 Electron-Hülle (F8)
- **Dünne Hülle, gleicher Server:** Electron ersetzt nur das Chrome-Fenster. Der Server läuft weiter als eigener
  Prozess mit dem System-Node ≥ 26.9 (`node:ffi`; das eingebettete Node von Electron ist älter). Die Hülle startet bzw.
  findet den Server wie der Launcher (Lockfile, Token, Launcher-Code) und lädt `http://127.0.0.1:<port>/#code=…` in
  einem `BrowserWindow` mit dauerhafter Partition.
- **Sicherheit:** `contextIsolation`, `sandbox`, kein `nodeIntegration`, kein Preload in v1; Navigation nur auf den
  eigenen Origin, Popups desselben Origins als neues Fenster, externe Links nur http(s) über `shell.openExternal`;
  Berechtigungen nur Benachrichtigungen.
- **Tray:** Symbol mit Zahl wartender Sessions (aus dem Fenstertitel „(n) Parallax“, kein eigener Kanal nötig) und
  Taskleisten-Overlay; Klick öffnet bzw. zeigt das Fenster; Menü „Öffnen“, „Neue Session …“, „Fenster schließen“,
  „Parallax beenden …“ (öffnet den bestehenden Dialog „Server beenden“). Fenster schließen = verstecken: Seite und
  Web-Benachrichtigungen laufen weiter, ein Klick auf einen Toast holt das Fenster zuverlässig nach vorn.
- **Eine Instanz:** zweiter Start fokussiert das vorhandene Fenster; `parallax://` und Autostart zeigen auf
  `Parallax.exe`; AUMID für Toasts.
- **Chrome bleibt Rückfall:** Fehlt die Electron-Laufzeit oder startet sie nicht (z. B. AppLocker), öffnet der Launcher
  wie heute Chrome. Einstellung „Fenster: Parallax-App | Chrome“.
- **Plattform:** zuerst Windows; Ubuntu behält Chrome/Chromium (Electron-Sandbox unter den Namensraum-Regeln von
  Ubuntu 24.04+ ist ein eigenes Thema).
- **Abhängigkeiten:** `electron` als devDependency im Paket `apps/electron` **ohne** Install-Skript (nicht in
  `allowBuilds`); die Laufzeit holt ein ausdrückliches Skript (offizielle Release-Datei, `ELECTRON_MIRROR` möglich) und
  prüft sie gegen `checksums.json` aus dem npm-Paket. `resedit` (reines JS) setzt Symbol und Versionsinfo von
  `Parallax.exe`. Version älter als 14 Tage (ADR-221).
- **Paket und Update:** Die Electron-Laufzeit wird eine eigene, getrennt versionierte Komponente
  (`runtime/electron-<v>`), signiert über `release.json` wie jede Datei; ein Update lädt sie nur, wenn sich ihre
  Version ändert (sonst würde jedes Update ~100 MB statt ~13 MB laden).
- **Setup.exe:** NSIS (`makensis` aus den Ubuntu-Paketen im CI, keine npm-Abhängigkeit). Die Setup.exe entpackt das
  Paket und ruft den bestehenden Installer (`dist/install.js`: Signatur, Kopie nach `versions/`, Agent SDK aus der
  Registry, Startmenü) auf; neu: Eintrag unter „Apps“ in den Windows-Einstellungen mit Deinstallation (Programmdateien,
  Startmenü, Autostart, Protokoll; Daten in `%LOCALAPPDATA%\Parallax` nur auf Wunsch). Node ≥ 26.9 und `claude` bleiben
  Voraussetzung (die Setup.exe prüft sie und erklärt den Weg).
- **Unsigniert:** Ohne Authenticode-Zertifikat warnt SmartScreen beim ersten Start („Weitere Informationen → Trotzdem
  ausführen“). Zip und `install.cmd` bleiben als zweiter Weg.

## 7. Risiken
- **Mehrere Sessions im selben Ordner** verfälschen den Gesamt-Diff ohne Worktree → Filter „nur Dateien dieser
  Session“ als Standard, Hinweis im Tab.
- **Push-Anmeldung:** Credential-Manager-Fenster können erscheinen; ohne Anmeldung → Rückfall ins Terminal.
- **Große Repos:** `worktree add` und `status` können dauern → asynchron, Timeouts, Ausgabegrenzen.
- **Electron:** unsignierte `Parallax.exe`/Setup.exe (SmartScreen, auf verwalteten Rechnern ggf. AppLocker) → Chrome
  bleibt Rückfall, Zip bleibt. Paketgröße → getrennte Laufzeit-Komponente.
- **Suche ohne Index:** bei sehr vielen Logs langsam → Worker, Abbruch, Grenze; Index als späterer Schritt.
